# 计划模板

## 必需工件路径

- `docs/requests/<request-id>/plan/plan.md`
- `docs/requests/<request-id>/plan/task-board.md`

## `plan/plan.md`

必需章节：

- 任务拆解
- 功能拆解明细
- 依赖关系
- 整洁性与复杂度控制
- 模式决策与替代方案
- 代码上下文与影响范围
- 并行执行建议（含是否值得启用 workflow）
- 触发与上下文准备
- 受影响文件或模块
- 测试策略
- 观察与人工介入点
- 回滚说明

### `任务拆解`

每个任务至少写清：

- 任务目标
- 关联规格区域
- 受影响页面、模块、弹窗、抽屉、卡片、区块或流程节点
- 串行/并行属性
- 前置条件与完成条件
- 对 `execute` 的禁止猜测边界

### `功能拆解明细`

对于任务涉及的每一个功能单元，必须按实际形态继续细拆，直到 `execute` 可直接照此实现而不需要补猜需求。

如果是表单，至少写清：

- 表单所在页面或容器
- 表单用途
- 字段清单
- 字段顺序
- 每个字段的字段名
- 每个字段的业务含义
- 每个字段是必填还是选填
- 每个字段对应控件类型
- 默认值或回填规则
- 占位提示或帮助信息（如有）
- 可编辑/禁用条件
- 显隐条件
- 选项来源或联动关系
- 校验规则
- 提交按钮与触发方式
- 提交后的成功反馈、失败反馈与 loading 结束条件

如果是表格，至少写清：

- 表格所在页面或容器
- 表格用途
- 列顺序
- 每列列名
- 每列字段来源
- 每列展示格式
- 空值展示规则
- 行内操作
- 批量操作
- 排序/筛选/分页/滚动规则（如有）
- 空状态、异常状态、loading 状态及取消条件

如果是纯展示内容，至少写清：

- 展示所在页面或容器
- 展示字段清单
- 字段分组或布局方式
- 每个字段展示格式
- 空值展示规则
- 显隐条件
- 是否只读、可折叠、可跳转或可复制

如果是交互行为，至少写清：

- 触发入口
- 触发前置条件
- 点击或操作后的界面变化
- 调用的动作或副作用
- 是否需要二次确认
- 是否需要 loading
- loading 从何时开始
- loading 在什么成功/失败/中断条件下结束
- 成功提示、失败提示、重试方式

如果是流程型能力，至少写清：

- 起点与终点
- 关键步骤
- 分支条件
- 状态流转
- 异常分支
- 回退/重试规则
- 与其他页面、模块或服务的交接点

补充要求：

- 任何会影响实现正确性的未知项，必须在计划中写成“待确认项”或“已批准假设”，禁止留白。
- 任何字段、列、交互、状态、流程如果已经在 PRD/spec 中可确定，就必须落进计划，不得省略为“按常规实现”。

## `plan/task-board.md`

每个任务必需字段：

- 任务 ID
- 任务名称
- 状态
- 执行模式（串行 / 可并行）
- 执行人或执行说明
- 触发/前置条件
- 关联规格区域
- 覆盖功能单元
- 页面/模块/容器范围
- 整洁性约束或注意点
- 模式约束或抽象边界
- 代码上下文或影响面备注
- 关键交互与状态约束
- 测试切入点
- 待确认项或已批准假设
