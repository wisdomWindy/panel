# 缺陷来源

## 来源系统

当前 Codex 会话中的直接用户反馈，以及仓库内 PRD。

## 来源范围

`bilibili-live-tool` 免费版桌面应用的“提醒配置 -> 上舰特效”。

## 缺陷标识

`captain-effect-preset-catalog`

## 标题

上舰特效内置模板缺失，与 PRD 的 10+ 预设及“金色尊享”示例不一致。

## 已观察行为

特效模板下拉框只出现已保存的 `captain-default`，Rust IPC 返回的 `presets` 是空数组，页面因当前配置不在目录中而临时补一个原始 ID 选项。

## 期望行为

内置至少 10 个可选特效模板，包含“金色尊享”；选择后模板的配色和视觉风格对预览及实际特效生效。

## 复现线索

1. 打开“提醒配置 -> 上舰特效”。
2. 展开“特效模板”下拉框。
3. 只看到 `captain-default`，看不到“金色尊享”或 PRD 要求的其他预设。

## 受影响模块或页面

- `src/renderer/views/captain-effect/index.vue`
- `src/renderer/components/media/CaptainEffectSurface.vue`
- renderer media contract/adapter
- Rust `ipc::media::captain_snapshot`

## 可用截图、日志或评论

未提供截图或日志；用户提供了可直接复现的页面行为，仓库代码可直接证明空目录根因。

## 原文证据索引

- U1: “上舰特效的特效模板里面怎么只有captain-default一个，应该多内置几个，PRD文档中不是有金色尊享特效选项吗”
- P1: PRD 6.4 / US-005 验收标准：“支持 10+ 预设模板、自定义配色与音效，特效展示正常”。
- P2: PRD 9.6.3 配置页示例：“特效模板：[金色尊享]”。
- P3: PRD 9.6.4：“模板选择 / 下拉 / 10+ 预设模板”。

## 闭集修复范围

- 提供不少于 10 项的内置模板目录，必须包含“金色尊享”。
- 模板目录向前端提供 ID、显示名与默认主/副色。
- 页面选择模板时应用对应默认配色，后续仍可手动修改。
- Canvas 根据 `presetId` 呈现至少在装饰形态上可区分的视觉效果，并保留减少动效和生命周期清理。
- 保留 `captain-default` 及未知旧 `presetId` 的兼容降级。
- 补充目录数量、金色尊享、合约适配和渲染分支的回归验证。

## 开放问题与缺失上下文

PRD 只明示“金色尊享”名称与 10+ 数量，其他模板命名、配色和装饰细节未指定。用户本次明确要求“多内置几个”，因此允许使用可识别的主题命名和保守的 Canvas 装饰变体补齐数量，不引入外部素材、新权限或新媒体格式。
