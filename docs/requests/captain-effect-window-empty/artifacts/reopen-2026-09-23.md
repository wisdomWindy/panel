# Reopen Evidence: Captain Effect Preview Still Empty

## Source

- Type: direct user defect report
- Date: 2026-09-23
- Verbatim evidence: "上舰特效页面的预览按钮弹出的特效窗口里什么都没有，至少给的特效演示"

## Observed And Expected

- Observed: clicking Preview opens the effect window, but the window contains no visible effect.
- Expected: the first preview window shows at least the configured captain-effect demonstration.
- Reproduction scope: `#/captain-effect` preview action in the desktop app.

## Scoped Code Facts

- The effect capability grants `captain-effect-current` but not the Tauri core event-listen permission.
- `EffectWindowRoot.vue` awaits `listenDesktop` and queries `captain_effect_current` inside the same `try` block.
- Therefore, an event-listener permission failure prevents both the live listener and the current-payload query, leaving `payload` null and the transparent canvas empty.

## Closed-World Fix Allowlist

- Permit the restricted effect window to listen for the existing `captain_effect_trigger` event.
- Keep the current-payload query able to populate the first frame even when event subscription fails.
- Add regression coverage for capability permissions and listener/query failure isolation.
- Do not add new controls, copy, template semantics, navigation, or unrelated media behavior.

## Intake Result

- Classification: `S2 scoped`, because the defect crosses Tauri capability and Vue startup lifecycle boundaries.
- No unresolved product decision or external blocker.
