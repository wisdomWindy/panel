# 功能缺口收口 - 待澄清问题

## 问题 1：插件配置能力本次做到什么深度

**问题**：插件管理页面的“配置”是否需要在本次补齐为可编辑表单？

**答案**：当前代码和审查结论的主要缺口是“页面没有接入真实运行链路”，配置弹窗目前至少需要展示真实配置快照；若现有插件没有稳定的 `configSchema` 驱动 UI，不强行扩展到完整可编辑表单。

**最终决定**：本次将插件配置能力收口为“展示真实配置快照 + 支持读取当前配置”，不新增复杂动态表单生成器。

**影响区域**：插件系统页面、spec/spec.md - 页面与模块设计

---

## 问题 2：配置导入导出是否采用新扁平结构

**问题**：设置页当前导出是分组结构，configStore 又是扁平核心配置，是否需要完全统一为一个新 schema？

**答案**：本次目标是收口可用性，不应引入高成本 schema 迁移；但必须让导入导出结构能覆盖当前核心配置域，并能明确映射到各 store。

**最终决定**：使用“统一顶层对象 + 各配置域子对象”的结构，导入时做显式映射写回，不做全局 schema 重构。

**影响区域**：设置页导入导出、spec/spec.md - API 与数据契约

---

## 问题 3：多语言闭环的最小覆盖范围

**问题**：本次是否需要把整个项目所有页面一次性全部国际化？

**答案**：当前用户要求是把审查出的未完善功能收口，不是开启新一轮全量国际化。应优先覆盖审查中明确发现的问题集中区。

**最终决定**：本次至少覆盖 `App.vue` 导航、`dashboard/index.vue`、`settings/index.vue`、`LanguageSettings.vue` 及其相关 i18n key；其他页面保留为后续扩展范围。

**影响区域**：多语言闭环验收、spec/spec.md - 范围内 / 范围外

---

## 问题 4：自动录制的触发入口

**问题**：自动录制是否需要新增新的事件流或后台轮询？

**答案**：当前代码已存在 `autoRecordStart` 事件与 `handleAutoRecordStart()` 占位逻辑，直接在现有入口闭环最稳妥。

**最终决定**：本次仅收口现有 `autoRecordStart` 入口，不扩展新的自动触发机制。

**影响区域**：录制闭环、spec/spec.md - 用户流程 / 录制模块设计

---

## 问题 5：TDD 在本次中的执行边界

**问题**：并非所有页面交互都易于在当前仓库内做完整组件测试，如何满足 workflow 的 TDD 约束？

**答案**：对可抽离的行为变化采用测试先行，例如插件安装路径解析与 manager 行为、配置导入导出映射、录制上下文构造等；对依赖 Electron 真实环境的页面链路，记录为 TDD 局部适用并用静态验证 + 命令验证补足。

**最终决定**：本次对可测试的纯逻辑和服务层行为执行 red -> green -> refactor；对 Electron 运行时链路在验证阶段补充手工/静态证据并记录原因。

**影响区域**：plan/plan.md、verification/verification.md
