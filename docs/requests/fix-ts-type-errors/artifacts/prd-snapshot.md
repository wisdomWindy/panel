# 问题规范化描述

## 问题定义

项目 TypeScript 类型检查失败，存在 100+ 个类型错误，涉及 16 个源文件。错误阻碍了 CI/CD 流水线中的类型检查步骤，且降低了 IDE 的类型提示和错误检测能力。

## 错误分类

### A. 模块声明缺失（3 处）
需要为无类型声明的第三方模块添加 `.d.ts` 声明文件。

### B. 类型定义不完整（18 处）
`plugin/types.ts` 缺少多个导出类型，`plugin-loader.ts` 和 `plugin-manager.ts` 引用了不存在的导出。需要补全类型定义或修正导入。

### C. IPC 接口类型不完整（10 处）
`window.electron` 的类型定义缺少多个方法签名。需要扩展 IPC 接口类型。

### D. unknown 类型未断言（~60 处）
`window.electron.invoke()` 返回 `unknown`，调用处需要添加类型断言。这是最大批量的错误。

### E. 类型不匹配（5 处）
包括 `undefined` vs `null`、字面量类型不兼容等。需要修正类型定义或添加类型守卫。

### F. 未使用声明（10 处）
导入了但未使用的类型和变量，需要删除或使用。

### G. 回调参数类型不兼容（3 处）
`on` 方法的回调签名过于宽泛，需要泛型支持或类型断言。

## 修复策略

1. 优先修复类型定义层（A/B/C），因为下游修复依赖正确的类型
2. 批量修复 unknown 类型断言（D），使用统一的模式
3. 逐个修复类型不匹配（E）
4. 清理未使用声明（F）
5. 修复回调类型（G）

## 验收标准

- `npm run type-check` 通过（exit code 0）
- 不引入新的 lint 错误
- 不改变运行时行为
