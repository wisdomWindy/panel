# Spec: 礼物音效系统

## Background and Goals
**背景**：Bilibili直播助手v1.0已完成基础功能，v2.0需要新增礼物音效系统，提升直播互动体验。

**目标**：
1. 实现完整的礼物音效配置和播放功能
2. 提供直观的UI界面进行音效管理
3. 确保音效播放的实时性和稳定性
4. 支持批量配置管理

## In Scope
1. **礼物音效配置管理**
   - 通过bilibili API获取礼物列表
   - 为现有礼物配置音效文件
   - 音效文件上传和管理
   - 播放参数设置（音量、时长、模式等）
   - 配置的导入导出

2. **音效播放功能**
   - 礼物事件监听和音效触发
   - 音效队列管理
   - 音频播放控制
   - 播放日志记录

3. **UI界面**
   - 礼物音效配置页面
   - 音效预览功能
   - 批量操作界面

## Out of Scope
1. **手动添加礼物**：礼物列表完全通过bilibili API获取，用户不能手动添加或修改礼物信息
2. **音频格式转换**：仅支持MP3格式，不支持其他格式转换
3. **云端同步**：配置仅本地存储，不支持云端同步
4. **音效推荐库**：不提供内置音效库
5. **实时音效编辑**：不支持在线编辑音效文件
6. **多房间支持**：仅支持单直播间配置

## Trigger and Start Conditions
**触发条件**：
1. 用户连接Bilibili直播间
2. 用户配置了至少一个礼物音效绑定
3. 音效文件存在且可访问

**启动条件**：
1. 应用启动并加载配置
2. WebSocket连接建立
3. 音频设备初始化完成

## User Flow
1. **配置流程**：
   - 打开礼物音效配置页面
   - 系统自动通过bilibili API获取礼物列表并展示
   - 用户从礼物列表中选择要配置音效的礼物
   - 用户上传音效文件（用户不需要配置礼物信息，只需配置音效文件）
   - 设置播放参数
   - 保存配置

2. **播放流程**：
   - 直播间收到礼物
   - 查询礼物音效配置
   - 检查冷却时间和优先级
   - 添加到音效队列
   - 按优先级播放音效
   - 记录播放日志

3. **管理流程**：
   - 查看所有配置
   - 批量启用/禁用
   - 导入导出配置
   - 预览音效效果

## Page and Module Design
**页面设计**：参考`design/page-design.md`

**模块设计**：
1. **主进程模块**（src/main/modules/gift-sound/）：
   - `audio-player.ts`：音频播放器，负责实际的音频播放
   - `sound-queue.ts`：音效队列管理，处理优先级和播放顺序
   - `index.ts`：模块入口，处理IPC通信

2. **渲染进程模块**（src/renderer/modules/gift-sound/）：
   - `types.ts`：类型定义

3. **渲染进程服务**（src/renderer/services/）：
   - `gift-sound-service.ts`：礼物音效服务，处理业务逻辑
   - `bilibili-gift-service.ts`：Bilibili礼物服务，获取和管理礼物列表

4. **状态管理**（src/renderer/stores/）：
   - `gift-sound.ts`：Pinia store，管理配置状态
   - `bilibili-gifts.ts`：Pinia store，管理Bilibili礼物列表

5. **UI组件**（src/renderer/views/）：
   - `gift-sound/index.vue`：主配置页面
   - 组件包括：礼物列表（从API获取）、音效配置表单、预览功能等

## API and Data Contracts
**数据模型**：参考PRD文档中的SQL定义

**API接口**：参考PRD文档中的TypeScript接口定义

**Bilibili API**：
- 获取礼物列表：通过Bilibili API获取当前直播间的礼物列表
- 礼物数据结构：包含礼物ID、礼物名称、礼物图片、礼物价格等
- 礼物信息完全由API提供，用户不能手动添加或修改礼物信息

**IPC通信**：
- `gift-sound:play`：播放音效
- `gift-sound:stop`：停止播放
- `gift-sound:preview`：预览音效
- `gift-sound:config:get`：获取配置
- `gift-sound:config:set`：设置配置
- `bilibili:gifts:get`：获取Bilibili礼物列表
- `bilibili:gifts:refresh`：刷新Bilibili礼物列表

## Context and Dependency Sources
1. **Bilibili WebSocket**：礼物事件数据源
2. **Bilibili API**：礼物列表数据源
3. **Web Audio API**或**Howler.js**：音频播放
4. **SQLite**：配置和日志存储
5. **Electron IPC**：主进程与渲染进程通信
6. **Vue 3 + TypeScript**：前端框架
7. **Pinia**：状态管理
8. **Element Plus**：UI组件库

## Edge Cases
1. **Bilibili API请求失败**：显示错误提示，提供重试机制
2. **Bilibili API返回空列表**：显示空状态提示
3. **音效文件缺失**：跳过播放，记录警告日志
4. **音效文件损坏**：跳过播放，记录错误日志
5. **音频设备异常**：跳过播放，提示用户检查设备
6. **音效队列满**：丢弃最旧的音效，优先播放新音效
7. **网络延迟**：礼物事件延迟到达，音效播放相应延迟
8. **配置冲突**：同一礼物多次配置，以最后一次为准
9. **大文件上传**：文件超过10MB限制，提示用户压缩或裁剪
10. **并发播放**：多个音效同时播放，按优先级队列处理
11. **礼物列表刷新**：支持手动刷新礼物列表，获取最新礼物信息

## Acceptance Criteria
1. **功能验收**：
   - [ ] 能够通过bilibili API获取礼物列表
   - [ ] 用户不能手动添加或修改礼物信息
   - [ ] 能够为现有礼物绑定音效文件
   - [ ] 每个礼物最多上传一个音频文件
   - [ ] 能够设置播放参数（音量、时长、模式等）
   - [ ] 能够预览音效效果
   - [ ] 能够导入导出配置
   - [ ] 能够批量管理配置

2. **性能验收**：
   - [ ] 音效触发延迟 < 500ms
   - [ ] 音效播放与礼物事件同步误差 < 100ms
   - [ ] 支持同时处理 10+ 个礼物/秒的音效队列
   - [ ] CPU占用增加 < 5%
   - [ ] 内存占用增加 < 50MB

3. **兼容性验收**：
   - [ ] 支持MP3格式音效文件
   - [ ] 音效文件大小支持 1KB ~ 10MB
   - [ ] 支持系统默认音频设备
   - [ ] 不影响其他音频播放

4. **用户体验验收**：
   - [ ] 界面直观易用
   - [ ] 操作反馈及时
   - [ ] 错误提示清晰
   - [ ] 支持响应式布局

## Human Review and Handoff
**人工审核点**：
1. 配置页面UI设计审核
2. 音效播放效果测试
3. 性能测试验证
4. 用户体验测试

**交接点**：
1. 开发完成后提交测试
2. 测试通过后发布版本
3. 用户文档编写
4. 用户培训和支持

## Risks
1. **技术风险**：
   - Bilibili API稳定性和可用性
   - Bilibili API请求频率限制
   - Web Audio API兼容性问题
   - 音频播放性能瓶颈
   - 跨平台音频设备差异

2. **用户体验风险**：
   - Bilibili API加载失败导致无法配置
   - 配置复杂度过高
   - 音效播放干扰直播内容
   - 移动端体验不佳

3. **项目风险**：
   - 开发周期紧张
   - 测试覆盖不足
   - 用户反馈不及时
   - Bilibili API变更导致功能失效
