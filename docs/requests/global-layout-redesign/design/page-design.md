# 页面设计

## 页面目标

修复渲染端 Tailwind 样式在 Electron/Vite 构建链路中的不稳定问题，确保页面样式由本地构建产物提供；同时统一约束 `src/renderer/**/*.vue` 仅通过 Tailwind utility class 表达页面样式，不再依赖 `<style>` 标签、`style` 属性或运行时注入样式。

## 目标用户或场景

- 桌面端直播助手的日常使用者，需要稳定一致的页面布局与视觉反馈
- 本仓库的前端维护者，需要可构建、可追踪、可审查的样式来源

## 布局结构

- `App.vue` 继续作为全局壳层，负责头部、侧栏、主内容区
- `Login.vue` 作为未连接状态的全屏入口页
- `views/*.vue` 页面保持各自业务布局，不新增独立样式文件或局部样式块

## 视觉层级

- 全局背景、卡片、标题、按钮层级继续由 Tailwind class 控制
- 视觉差异仅通过 utility class、状态 class、Element Plus 自带结构实现
- 禁止在页面组件内重新引入局部 CSS 来覆盖层级

## 区块拆解

- 样式供应链：从 CDN 注入切换为 `main.ts` 引入本地 Tailwind 样式入口
- 页面组件：保留现有 class 驱动布局，确认无 `<style>` 或 `style` 属性残留
- 文档工件：记录“仅允许 Tailwind class 样式”的仓库级约束

## 样式方向

- 页面样式仅允许通过 Tailwind utility class 表达
- 可以继续使用 Tailwind 任意值类，如 `bg-[#F5F6FA]`、`h-[calc(100vh-100px)]`
- Element Plus 组件本身的结构与功能属性保留，但不再通过页面内 style 机制做补充覆盖

## 交互骨架

- 不修改现有业务交互、表单逻辑、路由跳转和弹窗行为
- 本次只修复样式来源与样式表达约束，不引入新交互

## 响应式行为

- 维持当前桌面端优先布局
- Tailwind 本地构建需覆盖现有页面中使用到的所有 class，避免生产构建丢失样式

## 设计风险

- 如果 Tailwind 本地入口未正确接入，页面会出现 class 存在但样式缺失的问题
- 如果未来新增组件重新引入 `<style>` 或 `style` 属性，会破坏当前约束，需要在 review 中继续把关
