# 直播录制功能 - 澄清记录

## 问题 1：FFmpeg 集成方式

**问题**: 使用 fluent-ffmpeg 库调用系统 FFmpeg，还是打包 FFmpeg 二进制文件？

**回答**: MVP 阶段使用 fluent-ffmpeg 调用系统 FFmpeg。用户需自行安装 FFmpeg 并确保在系统 PATH 中。

**最终决策**: 使用 fluent-ffmpeg + 系统 FFmpeg。启动时检测 FFmpeg 可用性，不可用时显示安装引导。

**影响规格区域**: 主进程录制模块、设置页面、错误处理

## 问题 2：直播流获取方式

**问题**: 如何从 Bilibili 直播间获取直播流 URL？

**回答**: 复用现有 `bilibili-api.ts` 中的连接逻辑，通过 Bilibili 直播 API 获取直播流 URL。录制模块监听已连接的直播间状态，自动获取流地址。

**最终决策**: 复用现有连接模块，录制服务通过 IPC 获取当前直播流 URL。

**影响规格区域**: 录制服务、IPC 通道设计

## 问题 3：高光自动触发的弹幕阈值

**问题**: 弹幕数量达到多少时触发高光标记？

**回答**: 默认阈值为 10 秒内 30 条弹幕。可在设置中自定义。

**最终决策**: 默认 30 条/10 秒，可配置。

**影响规格区域**: 高光检测器、设置页面、RecordingConfig

## 问题 4：高价值礼物的默认阈值

**问题**: 礼物价值达到多少舰长数时触发高光标记？

**回答**: 默认阈值为单次礼物价值 >= 100 舰长数。可在设置中自定义。

**最终决策**: 默认 100 舰长数，可配置。

**影响规格区域**: 高光检测器、设置页面、RecordingConfig

## 问题 5：分段录制的技术实现

**问题**: 分段录制如何在关键帧处分段？

**回答**: 使用 FFmpeg 的 `-segment_time` 和 `-f segment` 输出格式，或在主进程监控文件大小/时长后手动切换输出文件。

**最终决策**: 使用 FFmpeg segment muxer 实现分段录制，确保在关键帧处分段。

**影响规格区域**: 录制引擎

## 问题 6：硬件加速支持

**问题**: 是否需要在 MVP 阶段支持硬件加速编码？

**回答**: MVP 阶段不支持硬件加速，使用软件编码（libx264 / libx265）。

**最终决策**: MVP 阶段使用软件编码，后续版本可选支持硬件加速。

**影响规格区域**: 录制引擎、设置页面

## 问题 7：录制文件元数据存储

**问题**: 使用 SQLite 还是独立 JSON 文件存储录制元数据？

**回答**: 复用现有 electron-store 方案，新增 recordings 和 highlights 数据存储。

**最终决策**: 使用 electron-store 存储录制元数据，保持与现有数据架构一致。

**影响规格区域**: 数据库模块、IPC 通道

## 问题 8：高光标记冷却时间

**问题**: 连续触发高光时如何处理？

**回答**: 设置冷却时间，同一类型的高光标记在冷却期内不会重复触发。

**最终决策**: 默认冷却时间 10 秒，可配置。

**影响规格区域**: 高光检测器

## 问题 9：录制状态推送机制

**问题**: 主进程如何实时推送录制状态到渲染进程？

**回答**: 使用 Electron 的 IPC 事件推送机制（webContents.send），渲染进程通过 ipcRenderer.on 监听。

**最终决策**: 使用 IPC 事件推送，每秒更新一次录制状态（时长、文件大小）。

**影响规格区域**: IPC 通道设计、录制服务

## 问题 10：存储路径默认值

**问题**: 录制文件的默认存储路径是什么？

**回答**: 默认存储在用户目录下的 `BilibiliLiveTool/recordings/` 文件夹。

**最终决策**: 默认路径为 `{用户目录}/BilibiliLiveTool/recordings/`，可在设置中自定义。

**影响规格区域**: 录制配置、文件管理器
