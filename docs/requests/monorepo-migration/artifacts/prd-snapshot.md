# PRD快照：Monorepo架构迁移

## 来源
**文档路径**：用户需求
**快照时间**：2026-06-25

## 业务背景
当前项目采用传统的单一项目结构，所有代码都在src目录下。为了提升代码组织性和可维护性，需要将项目架构调整为monorepo，将直播助手相关功能模块统一管理。

## 核心需求

### 1. 重新组织项目目录结构
**需求描述**：将项目调整为monorepo结构
**优先级**：高
**验收标准**：
- 使用pnpm workspace管理多个包
- 直播助手功能模块统一在packages目录下
- 保持现有功能完整性

### 2. 目录结构设计
**需求描述**：设计合理的monorepo目录结构
**优先级**：高
**验收标准**：
- packages/main - 主进程模块
- packages/renderer - 渲染进程模块
- packages/preload - 预加载脚本模块
- packages/shared - 共享类型和工具模块

### 3. 配置monorepo工具链
**需求描述**：配置pnpm workspace
**优先级**：高
**验收标准**：
- 创建pnpm-workspace.yaml配置
- 更新package.json配置
- 配置各子包的依赖关系

### 4. 更新构建和开发脚本
**需求描述**：更新构建和开发脚本
**优先级**：中
**验收标准**：
- 构建脚本正常工作
- 开发脚本正常工作
- 测试脚本正常工作

## 技术约束

### 现有架构
- 主进程：src/main/
- 渲染进程：src/renderer/
- 预加载脚本：src/preload/
- 共享类型：src/typings/

### 依赖关系
- pnpm workspace
- Vue 3 + TypeScript
- Electron
- Vite

## 验收标准

### 功能验收
1. 项目目录结构符合monorepo规范
2. 直播助手功能模块统一在packages目录下
3. pnpm workspace配置正确
4. 构建和开发脚本正常工作
5. 现有功能保持完整

### 性能验收
1. 构建时间不显著增加
2. 开发体验保持良好
3. 依赖管理清晰

### 兼容性验收
1. 兼容现有功能
2. 不影响其他模块
3. 支持多平台运行

## 风险评估

### 技术风险
1. 迁移过程中可能出现依赖问题
2. 构建配置可能需要调整
3. 类型引用可能需要更新

### 业务风险
1. 迁移期间功能可能受影响
2. 开发流程可能需要调整
3. 团队学习成本

## 实施建议

### 开发阶段
1. 第一阶段：设计monorepo目录结构
2. 第二阶段：迁移代码到新目录
3. 第三阶段：配置pnpm workspace
4. 第四阶段：更新构建和开发脚本

### 测试策略
1. 单元测试：验证各模块功能
2. 集成测试：验证模块间交互
3. 端到端测试：验证完整功能

### 发布计划
1. 迁移完成后进行内部测试
2. 测试通过后发布新版本
3. 用户反馈后优化
