# 插件系统待澄清问题

## 问题 1：插件格式

**问题**：采用什么格式的插件？（JavaScript 模块、TypeScript 编译后的模块、或者特定格式）

**答案**：采用 JavaScript 模块格式，插件开发者使用 TypeScript 开发后编译为 JavaScript。插件包为包含 manifest.json 和 index.js 的目录或 zip 文件。

**最终决定**：插件格式为 JavaScript 模块，支持 ES Module 语法。插件包为目录或 zip 文件，包含 manifest.json 和 index.js。

**影响区域**：插件加载器、插件格式验证

## 问题 2：插件存储位置

**问题**：插件安装到哪个目录？（应用数据目录、用户目录、或者应用内）

**答案**：插件安装到应用数据目录下的 plugins 文件夹。具体路径为：
- Windows: `%APPDATA%/bilibili-live-tool/plugins/`
- macOS: `~/Library/Application Support/bilibili-live-tool/plugins/`
- Linux: `~/.config/bilibili-live-tool/plugins/`

**最终决定**：插件安装到应用数据目录下的 plugins 文件夹。使用 Electron 的 app.getPath('userData') 获取路径。

**影响区域**：插件加载器、插件管理器

## 问题 3：插件权限模型

**问题**：插件可以访问哪些 API？是否需要权限声明？

**答案**：插件需要声明权限，权限类型包括：
- danmaku: 弹幕读写
- gift: 礼物监听
- captain: 舰长监听
- config: 配置读写
- effect: 特效注册
- ui: UI 扩展

**最终决定**：插件必须在 manifest.json 中声明所需权限。插件 API 暂露时检查权限，未声明权限的 API 调用将被拒绝。

**影响区域**：插件 API、插件沙箱

## 问题 4：插件隔离级别

**问题**：插件运行在独立的沙箱中，还是共享渲染进程？

**答案**：当前阶段使用渲染进程内沙箱，通过 Function 构造函数创建受限的执行环境。后续版本可以考虑使用 Web Worker 或 iframe 隔离。

**最终决定**：使用渲染进程内沙箱，通过 Function 构造函数创建受限的执行环境。插件代码在沙箱中执行，无法访问全局对象。

**影响区域**：插件沙箱

## 问题 5：插件分发方式

**问题**：如何获取和安装插件？（本地安装、插件市场、或者两者都支持）

**答案**：当前阶段仅支持本地安装，用户手动下载插件包后通过界面安装。后续版本可以考虑添加插件市场。

**最终决定**：当前阶段仅支持本地安装。用户通过设置页面的「安装插件」按钮选择插件文件或拖拽到指定区域进行安装。

**影响区域**：插件管理界面

## 问题 6：插件版本兼容性

**问题**：如何处理插件与主应用版本的兼容性？

**答案**：插件在 manifest.json 中声明 minAppVersion 字段，表示支持的最低应用版本。加载时检查当前应用版本是否满足要求。

**最终决定**：插件必须在 manifest.json 中声明 minAppVersion 字段。加载时检查当前应用版本，如果不满足要求则显示警告，允许用户选择是否强制安装。

**影响区域**：插件加载器、插件格式验证

## 问题 7：插件配置存储

**问题**：插件配置存储在哪里？（独立文件、数据库、或者统一配置系统）

**答案**：插件配置存储在应用的统一配置系统中，使用 config store 管理。每个插件的配置以插件 ID 为 key 存储。

**最终决定**：插件配置存储在应用的统一配置系统中。使用 config store 管理，以插件 ID 为 key 存储配置。

**影响区域**：插件 API、配置管理

## 问题 8：插件更新机制

**问题**：插件如何更新？（手动更新、自动检查更新）

**答案**：当前阶段仅支持手动更新，用户下载新版本插件后重新安装。后续版本可以考虑添加插件自动更新。

**最终决定**：当前阶段仅支持手动更新。用户下载新版本插件后，通过「安装插件」功能重新安装，旧版本将被覆盖。

**影响区域**：插件管理器
