## 2. 设计决策评审

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| 独立 Python HTTP 服务而非内联推理 | 通过 | 上游依赖 PyTorch、建议独立环境；可独立降级/升级 |
| 复用 `cloud` 引擎槽位承载 Qwen3-TTS | 通过 | 前端已有 `system \| cloud` 与“云端不可用”提示，零契约破坏 |
| AI 回复用 SAPI `SpeakStream` 而非 rodio | 通过 | 唯一能保住 `output_device_id` 音频路由的方案；避免语音误入观众端 |
| 配置存 `t_app_setting` JSON 而非新表/新列 | 通过 | 免数据库迁移，`SCHEMA_VERSION` 不变，回滚更安全 |
| 音色用 `qwen3:` 前缀区分后端 | 通过 | 单字段即可路由，历史配置零迁移 |
| 语速倍率折算为指令而非重采样 | 通过（有取舍） | 避免二次重采样损伤音质；代价是语速不完全线性 |
| 修改 Cloud 回退链加入 System | 通过 | 修正了“选择云端后服务故障即静音”的直播风险；试听路径仍严格验证所选引擎 |

## 4. 安全与合规复核

- 无明文密钥：服务无鉴权、无需密钥；`baseUrl` 为普通配置项。
- 无硬编码绝对路径：临时文件走 `std::env::temp_dir()`，模型权重路径由命令行参数给出。
- 服务默认仅监听 `127.0.0.1`，README 明确“不要直接暴露公网”。
- 许可证：Apache-2.0，商用自托管允许；发布二进制时需随附声明与 NOTICE。
- 隐私：播报文本含观众用户名，经本机服务合成，不出网（除非 `baseUrl` 指向远程）。
