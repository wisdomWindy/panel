## 来源摘要

用户要求移除主播账号主动发送弹幕和互动面板弹幕指令能力。结合上一轮可行性审查的会话上下文，“以主播账号发送弹幕”是手动、自动、事件触发和插件发送共同依赖的底层能力。

## 关键业务目标

- 删除主动向直播间发送弹幕的产品能力，而不是仅隐藏一个按钮。
- 删除互动面板弹幕指令的产品实现或宣称。
- 保留只读的弹幕接收与消费能力。

## Greenfield scaffold sensitivity

不适用：这是既有产品能力删除请求。

## 显式行为约束

- source-backed：删除主播账号主动发送弹幕能力。
- source-backed：删除互动面板弹幕指令能力。
- source-derived-safe：手动发送、定时/随机发送、触发词回复、礼物感谢回复、AI/插件发送均无法在移除底层发送能力后继续保留，属于必要依赖闭包清理。
- code-fact-backed：弹幕接收、展示、统计、TTS 不依赖主动发送，应保持。
- code-fact-backed：官方资料快照用于证明平台能力边界，不作为本次产品代码；保持原样。

## Closed-world product scope allowlist

允许的产品可见修改仅包括：

- 删除“发送弹幕”按钮、弹窗、测试发送入口和 Cookie 发送提示。
- 删除弹幕池与自动发送相关菜单、页面、设置项、统计项和文案。
- 删除触发词自动回复、礼物/舰长自动感谢、角色自动回复和插件发送接口。
- 删除产品自有文档中的主动发送与互动面板弹幕指令能力宣称。

不允许新增替代发送方案、覆盖层消息、第三方接口或新的交互。

## 表单、表格、展示与交互

- 删除弹幕列表页的发送弹窗与触发按钮。
- 删除连接页“用于发送弹幕”的 Cookie 表单项。
- 删除弹幕池页面和菜单入口。
- 删除设置页自动发送、触发回复、礼物感谢配置。
- 删除插件侧 `sendDanmaku` API 及文档示例。

## 工作流与状态规则

- 删除所有能触发主动发送的定时器和事件响应。
- 删除发送成功率、已发送数量、感谢弹幕数量等发送侧状态。
- 保留收到弹幕、礼物、排行榜、TTS、录制高光等只读事件处理。
