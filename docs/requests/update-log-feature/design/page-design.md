# 更新日志功能 - 页面设计

## 页面目标

为 Bilibili 直播助手提供应用内的版本更新日志查看能力，包括更新日志详情页面、新版本特性弹窗、以及状态栏更新提示。用户无需离开应用即可了解产品迭代内容。

## 目标用户与场景

### 场景 1：主动查看更新日志
用户通过菜单栏「帮助 → 更新日志」或设置页面入口，打开更新日志页面，浏览历史版本的变更记录。

### 场景 2：被动接收新版本通知
用户完成应用更新后首次启动，自动弹出"新版本特性"弹窗，展示当前版本的更新摘要。

### 场景 3：发现新版本
应用运行期间检测到新版本，状态栏显示红点提示，用户点击后查看详情并跳转下载。

## 视觉层次

1. **主层级**: 更新日志页面标题和当前版本信息
2. **次层级**: 每个版本的版本号和日期
3. **内容层级**: 变更分类标题（新功能/改进/修复/破坏性变更）
4. **细节层级**: 具体变更条目

### 颜色方案

- 版本号: 使用 Element Plus 主题色 `#409EFF`
- 日期: 使用次要文字色 `#909399`
- 分类标签:
  - 新功能: 绿色 `#67C23A`
  - 改进: 蓝色 `#409EFF`
  - 修复: 橙色 `#E6A23C`
  - 破坏性变更: 红色 `#F56C6C`
- 更新提示红点: 使用 Element Plus 危险色 `#F56C6C`

## 分区详解

### 更新日志页面分区

| 区域 | 内容 | 交互 |
|------|------|------|
| 头部信息 | 当前版本号、最新版本号、下载按钮 | 点击下载跳转外部链接 |
| 版本列表 | 按时间倒序的版本记录 | 滚动浏览 |
| 版本卡片 | 版本号、日期、分类变更列表 | 无交互，纯展示 |

### 新版本特性弹窗分区

| 区域 | 内容 | 交互 |
|------|------|------|
| 标题 | 新版本特性 + 关闭按钮 | 点击 X 关闭 |
| 内容区 | 当前版本的更新摘要 | 滚动（内容过长时） |
| 底部 | 不再提醒复选框 + 确认按钮 | 勾选后记住选择 |

## 样式方向

- 遵循项目现有的 Tailwind CSS 类名风格
- 使用 Element Plus 组件库（el-card, el-dialog, el-button, el-tag, el-badge）
- 不使用 `<style>` 标签，不使用内联样式
- 更新日志页面使用与 Settings 页面一致的卡片布局
- 版本卡片使用 el-card 带阴影效果

## 交互骨架

### 更新日志页面

1. 页面加载 → 解析 CHANGELOG.md → 渲染版本列表
2. 检查更新 → 显示最新版本信息和下载按钮
3. 点击「前往下载」→ 打开外部浏览器跳转下载页

### 新版本特性弹窗

1. 应用启动 → 检查本地版本与已提示版本
2. 版本不同 → 弹出对话框展示更新摘要
3. 点击「知道了」→ 关闭弹窗，记录已提示版本
4. 勾选「不再提醒此版本」→ 记录到 localStorage

### 状态栏提示

1. 后台检查更新 → 发现新版本 → 显示红点
2. 点击红点 → 跳转到更新日志页面
3. 离线或检查失败 → 不显示任何提示

## 响应式行为

- 更新日志页面最小宽度: 800px
- 新版本特性弹窗宽度: 500px（固定）
- 版本卡片在窄屏下自动换行
- 弹窗在小屏幕上自适应宽度

## 设计风险

1. **CHANGELOG.md 解析**: 需要严格遵循 Keep a Changelog 格式，解析失败时需优雅降级
2. **版本号比较**: 需要正确实现 Semantic Versioning 比较逻辑
3. **网络检查时机**: 启动时检查不能阻塞主界面加载，需异步执行
4. **弹窗频率控制**: 需要妥善存储已提示版本，避免重复弹窗
