# 更新日志功能 - 待澄清问题

## 问题 1：更新检查源的仓库地址

**问题**: GitHub Releases API 需要指定仓库的 owner 和 repo，当前项目仓库地址是什么？

**答案**: 从 package.json 和项目结构推断，使用当前仓库地址。如未配置，提供配置项允许用户自定义。

**最终决定**: 使用环境变量或配置文件中的仓库地址，默认值为当前仓库。如无法获取，静默跳过更新检查。

**影响区域**: update-service.ts 的 checkForUpdates 方法

---

## 问题 2：CHANGELOG.md 的位置

**问题**: CHANGELOG.md 应该放在项目根目录还是其他位置？

**答案**: 遵循业界惯例，放在项目根目录。

**最终决定**: CHANGELOG.md 放在项目根目录，打包时包含在应用资源中。

**影响区域**: update-service.ts 的 parseChangelog 方法

---

## 问题 3：新版本特性弹窗的触发时机

**问题**: 弹窗应该在应用完全加载后显示，还是在加载过程中显示？

**答案**: 应该在应用完全加载后显示，避免影响启动性能。

**最终决定**: 在 main.ts 的 onMounted 回调中，使用 nextTick 确保 DOM 渲染完成后再检查并弹出。

**影响区域**: main.ts 的初始化逻辑

---

## 问题 4：更新检查的频率

**问题**: PRD 中提到运行期间每隔 4 小时检查一次，是否需要实现定时器？

**答案**: 当前阶段仅实现启动时检查，运行期间的定时检查作为后续优化。

**最终决定**: 仅在应用启动时检查一次更新，不实现运行期间的定时检查。

**影响区域**: update-service.ts 的初始化逻辑

---

## 问题 5：侧边栏菜单入口位置

**问题**: 更新日志入口应该放在侧边栏的什么位置？

**答案**: 可以作为独立菜单项，或者放在「设置」菜单下作为子菜单。

**最终决定**: 作为独立菜单项放在侧边栏底部，使用 `Bell` 图标。

**影响区域**: App.vue 的侧边栏菜单

---

## 问题 6：下载页 URL 的配置

**问题**: 「前往下载」按钮的跳转 URL 应该如何确定？

**答案**: 从 GitHub Releases API 的 html_url 字段获取。

**最终决定**: 使用 GitHub Release 的 html_url 作为下载页 URL，无需额外配置。

**影响区域**: UpdateLog.vue 的下载按钮逻辑
