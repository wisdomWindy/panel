# Bilibili 直播助手 Tauri 重构 产品需求文档（PRD）

**创建日期**：2026-11-21

**文档状态**：定稿（单安装包・移除 ASR / 自动禁言 / 会员体系修订版）

**重构目标**：将原 Bilibili 直播助手重构为 **Tauri 框架 + Rust 核心 + 前端 WebView + Sidecar** 的桌面应用。

**合规边界**：工具为直播间只读监听、本地提醒、本地录制、本地 AI 文本生成与本地语音输出；**不提供任何自动或手动发送弹幕能力，不调用任何直播间写操作接口**。



***

## 0. 关键前提



1. **只读监听**：B 站直播间事件仅做只读接收，不设计任何发送弹幕、禁言、踢人、关注、点赞等主动操作命令、按钮或自动任务。

2. **单安装包交付**：产品为一个独立安装包，不分免费版 / 会员版，无充值入口、无登录体系、无会员引导、无功能锁。

3. **本地优先**：监听、过滤、统计、录制、AI 生成与语音输出均以本地为主，默认不上传用户数据；仅当用户主动配置外部 LLM 时，按 §12 的范围向用户指定端点发送组装后的上下文。

4. **AI 文本生成模型不内置**：软件本身不内置、不捆绑任何 LLM 模型权重。AI 文本生成模型由用户单独配置，支持国内外主流模型、第三方聚合 API、本地模型服务和自定义 OpenAI 兼容端点。

5. **AI 语音回复不发送弹幕**：AI 语音回复包含 "按规则生成回复文本 + 软件内显示 + 本地 TTS 播报到指定音频设备"。语音由 Bilibili 直播姬 / OBS 采集后输出给观众听到。**不调用 B 站发送弹幕接口，不提供发送按钮或发送 Command**。AI 语音回复默认关闭，需用户显式开启并完成音频路由确认。

6. **无服务端依赖**：除用户自行配置的 LLM 端点外，应用不依赖自建后端；不做账号体系、订单体系、模块分发体系。

7. **Sidecar 合规**：FFmpeg 使用现成 LGPL 预编译构建，随主包分发；不捆绑任何语音识别（ASR）组件与模型。

8. **数据可迁移**：历史配置、日志、统计可迁移；配置升级不丢失，迁移失败自动回滚。

9. **风控能力边界**：本地风控仅包含敏感词过滤与黑名单屏蔽，不包含任何对直播间用户的处置操作。

10. **录制授权提示**：直播录制仅用于主播本人或已获授权直播间的存档与二次创作；付费、私密、版权受限房间可能无可用流，应用不绕开任何平台限制。

## 1. 产品概述

### 1.1 产品愿景

打造一款集观众弹幕监控、智能观测、特效展示、直播录制、数据分析、AI 辅助互动于一体的 Bilibili 直播辅助工具，帮助主播降低直播运营成本，实时掌握直播间观众互动情况，同时满足内容存档和二次创作需求。

产品以单一桌面安装包交付，全部功能本地运行：



* 直播间只读数据监听、本地提醒、数据统计、敏感词与黑名单本地风控、弹幕语音播报、直播录制、多语言、基础 UI，以及 **AI 语音回复**（需用户自行配置外部 LLM 模型）。

* 无任何充值入口、登录入口、会员引导、功能付费墙，无任何自动发送弹幕或处置用户的能力。

### 1.2 目标用户



* Bilibili 全职 / 兼职游戏、娱乐、虚拟主播。

* 直播间运营团队成员，负责直播复盘、互动运营。

* 需要 24 小时无人值守挂机监控、维持直播间基础互动的虚拟主播、挂机直播间运营者。

## 2. 重构概述

### 2.1 重构背景

原产品功能覆盖弹幕监听、本地提醒、TTS、录制、AI 文案辅助等模块。为降低内存占用、提升并发性能、增强安全隔离和跨平台发布，决定采用 Tauri 框架重构。

Tauri 的核心优势：



* Rust 后端处理 WebSocket、规则引擎、录制、AI 调用、数据库等高负载任务。

* WebView 前端只负责 UI 渲染，降低内存占用。

* 通过 IPC Command / Event 实现前后端解耦。

* 通过 Capabilities 权限系统限制前端能力。

* 通过 Sidecar 集成 ffmpeg 等本地二进制。

* 支持自动更新、系统托盘、全局快捷键、通知、多窗口透明特效。

### 2.2 重构目标



1. 保持原产品保留功能，产品体验不降级。

2. 核心能力 Rust 化：WebSocket、敏感词、黑名单、录制控制、TTS 队列、AI 调用、数据库。

3. 前端轻量化：仅通过 `invoke` 和 `listen` 与 Rust 交互，不直接访问文件系统、数据库和密钥。

4. 安全增强：所有 IPC 命令在 Rust 侧做参数校验、类型校验、路径白名单。

5. 性能提升：空闲内存 ≤120MB，录制 + AI 模式内存 ≤200MB，CPU 增量 ≤15%。

6. 发布现代化：单安装包、单更新通道、签名校验、回滚。

### 2.3 重构原则



* **本地优先**：监听、过滤、统计、录制、AI 生成、TTS 输出均以本地为主。

* **只读监听**：B 站 WebSocket 仅接收事件，不设计任何发送或处置命令。

* **权限最小化**：Tauri Capabilities 按窗口分配权限，IPC 命令在 Rust 侧二次校验。

* **模块解耦**：AI 异常不影响监听、提醒、统计和录制。

* **数据兼容**：历史配置、日志、统计可迁移，迁移失败自动回滚。

* **可观测**：Rust `tracing` + 前端日志面板 + 本地日志文件；业务埋点仅落本地，不上报。

* **AI 模型不内置**：软件不捆绑任何 LLM 权重，由用户自行配置外部模型或本地模型服务。

* **AI 语音回复即时聊天化**：AI 生成文本必须短句、口语化、纯文本单段，禁止长文、分点、标题、Markdown、客套开场和 AI 自指。

* **AI 不发送弹幕**：AI 语音回复只生成文本、本地显示、本地 TTS 输出，不调用直播间发送接口。

### 2.4 成功指标与测试前置条件



| 指标              | 目标                      | 测试前置条件                                   |

## 4. 产品形态与数据目录

### 4.1 产品形态



* 单一桌面安装包，单更新通道。

* 应用内不出现任何充值、登录、会员、升级、付费引导入口。

* 不包含账号体系、订单体系、模块动态下载体系。

### 4.2 数据目录策略



* 应用标识符与数据目录在各平台按系统规范固定，升级覆盖安装时数据保留。

* 配置、日志、统计、AI 日志、录制文件分类存放：


  * `config/`：应用配置、模型档案、AI 人设与规则配置。

  * `data/`：SQLite 数据库（事件日志、统计、黑名单、敏感词、AI 日志）。

  * `recordings/`：录制文件与高光片段（目录可由用户在设置中更改）。

  * `logs/`：运行日志。

* 敏感字段（API Key）加密存储，与普通配置分离。

* 卸载应用时提示用户是否保留本地数据；用户可在设置中一键清空全部本地数据（见 §12）。

### 4.3 配置迁移



* 版本升级时自动迁移数据库结构，迁移前自动备份，迁移失败自动回滚到上一版本配置。

* 支持配置手动导入 / 导出；导出文件中 API Key 默认脱敏（见 §9.14、§11.3）。

## 5. 用户与场景

### 5.1 核心用户



* 全职 / 兼职游戏、娱乐、虚拟主播。

* 直播间运营与复盘人员。

* 24 小时无人值守挂机直播运营者。

### 5.2 用户画像

#### 用户画像 A：全职主播小王

**基本信息**：28 岁，全职游戏主播，每天直播 8 小时。

**痛点**：



* 直播时需要同时关注弹幕、操作游戏，分身乏术。

* 夜间挂机直播无人值守，无法回应观众弹幕，直播间氛围冷清。

* 容易错过舰长开通、大额礼物等高价值互动事件。

* 人工逐条回复弹幕效率极低。

**期望**：



* 舰长、大额礼物触发本地弹窗 + 音效提醒。

* 直播时由 AI 生成即时聊天风格的回复，经本地 TTS 输出到直播音频，让观众听到。

* 自动播报弹幕、完整记录直播数据，方便赛后复盘。

#### 用户画像 B：运营者小张

**基本信息**：25 岁，直播账号运营，负责互动策划、内容复盘。

**痛点**：



* 人工统计弹幕热度、送礼数据，复盘效率低下。

* 观众高频重复问题无法统一答疑，互动体验差。

* 缺少高光时刻自动记录、直播内容存档工具。

* 多场次直播人工回复工作量大，话术风格无法统一。

**期望**：



* AI 辅助归纳观众高频问题，生成短句回复建议并播报。

* 自定义 AI 人设，统一直播间互动话术风格。

* 自动录制直播内容、标记高光时刻，方便二次剪辑创作。

* 可视化数据看板，辅助直播运营策略优化。

#### 用户画像 C：兼职主播小李

**基本信息**：22 岁，大学生，兼职直播，每周直播 3-4 次。

**痛点**：



* 不熟悉 B 站直播协议，无法集中查看全量观众弹幕。

* 缺少免费直播数据统计工具，复盘难度高。

* 预算有限，不愿为辅助工具付费。

**期望**：



* 开箱使用直播间监控、弹幕播报、数据复盘、直播录制基础功能，无需付费解锁。

* AI 语音回复同样内置可用（自备模型 API 或本地模型）。

* 工具轻量、开箱即用，无付费干扰。

### 5.3 用户场景

#### 场景 1：日常连接直播间使用



1. 小李启动应用，选择房间并点击「连接」。

2. 应用建立只读 WebSocket 连接，弹幕、礼物、舰长、进场事件实时展示在面板。

3. 小李使用弹幕监控、语音播报、数据看板、直播录制等功能。

4. 小李配置外部 LLM 模型、AI 人设、TTS 输出设备，开启 AI 语音回复。

5. 观众弹幕后，AI 生成回复并播报，经 OBS / 直播姬输出给观众听到。

#### 场景 2：AI 语音回复配置与播报



1. 主播在 AI 模型配置中填写 Provider、Base URL、API Key、模型名与参数，可保存多个档案并指定默认模型。

2. 主播配置 AI 人设、说话风格、触发规则、敏感词和上下文范围。

3. 主播选择 TTS 输出设备，推荐虚拟音频设备，并在 OBS / 直播姬中添加对应音频源。

4. 主播点击测试播报，确认 OBS / 直播姬可见电平。

5. 主播显式开启「AI 语音回复」，首次开启完成音频路由确认。

6. 观众发送弹幕后，经敏感词、黑名单、身份过滤进入 AI 判定；命中规则后组装上下文调用 LLM。

7. AI 生成即时聊天风格短句回复，经敏感词过滤、长度截断后显示在软件内，自动进入 TTS 播报队列。

8. OBS / 直播姬采集该音频设备，观众听到 AI 回复语音。

9. 主播可随时暂停 AI 语音回复、暂停 / 跳过当前播报、清空队列、重新生成或复制文本。

10. 全程不产生任何发送弹幕请求。

#### 场景 3：夜间挂机直播监控



1. 主播连接直播间，开启弹幕语音播报、礼物 / 上舰提醒功能。

2. 配置敏感词过滤、黑名单规则，维护直播间展示内容。

3. 工具后台静默监听直播间全量事件，无任何主动操作。

4. 观众发送弹幕，工具本地展示、语音播报、留存日志。

5. 触发舰长、大额礼物事件，工具弹窗 + 音效提醒。

6. 主播可开启 AI 语音回复，让 AI 对弹幕生成短句回复并播报。

7. 主播次日通过数据看板、日志复盘整场直播数据与互动情况。

#### 场景 4：高光时刻自动录制



1. 系统实时监测直播间弹幕热度、礼物波动数据。

2. 检测到弹幕激增、热度暴涨，自动判定为高光时刻。

3. 自动录制高光前后 30 秒片段，独立保存为 MP4 文件。

4. 主播也可通过 F9 快捷键手动标记高光时刻。

5. 直播结束后，主播可在本地预览、剪辑、手动上传高光片段至 B 站。

#### 场景 5：舰长开通专属特效提醒



1. 工具监听直播间舰长开通事件，识别首次开通 / 续费类型。

4. 特效停留 5 秒后自动淡出，不影响直播画面。

#### 场景 6：全场直播存档录制



1. 主播连接直播间后，手动开启全程录制功能。

2. 工具通过 FFmpeg 拉取可用直播流，实时录制并标记高光节点。

3. 直播结束后停止录制，自动生成完整录播文件与独立高光片段。

4. 主播可本地预览、剪辑、手动上传至 B 站平台。

#### 场景 7：礼物音效绑定



1. 主播在提醒配置中为不同礼物绑定自定义 MP3 音效。

2. 独立调节各礼物音效音量，支持一键预览、批量配置、批量导入导出。

3. 直播间收到对应礼物时，按优先级队列播放绑定音效，不干扰其他音频。

#### 场景 8：敏感词与黑名单维护



1. 主播在风控中心查看内置分级敏感词库，新增、删除、导入、导出自定义词汇。

2. 命中敏感词的弹幕不展示、不播报、不进入 AI 上下文，过滤日志可查。

#### 场景 9：数据复盘与导出



1. 主播在数据看板查看在线人数、弹幕量、礼物收益、舰长数据及趋势曲线。

2. 在排行榜查看送礼榜、弹幕互动榜、舰长贡献榜。

3. 按时间范围查询历史统计，将看板数据、榜单数据导出为 CSV。

#### 场景 10：断网重连与异常降级



1. 网络中断后，工具按策略自动重连，期间状态栏显示重连状态。

2. LLM 端点不可用、超时或限流时，AI 语音回复不播报、记录失败并进入退避冷却，不影响监听、播报、统计与录制。

3. 音频设备被拔出或丢失时，停止 AI 语音播报并提示重新选择，不自动改到默认扬声器。

4. 录制流中断时按策略重连，超过重试次数后停止录制并提示，已保存片段不损坏。

## 9. 功能详细需求

### 9.1 直播间连接与弹幕接收

通过 WebSocket 全量连接 Bilibili 直播间，实时接收观众弹幕流、直播间各类事件流，毫秒级同步展示在本地面板，**仅做只读接收，无任何主动发送、操作直播间权限**。

**连接范围**：同一时间仅连接 1 个直播间；多房间同时监听不在本期范围内。

关键流程：



1. 用户填写「主播身份码」并点击「连接」。

2. 前端调用 `room_connect(identity_code)`，Rust 校验身份码格式（非空、≤128 字符、无控制字符）。

3. Rust 调用开放平台 `/v2/app/start`（入参 `code` = 主播身份码、`app_id` = 应用 ID），取回 `websocket_info.wss_link` 与 `auth_body`，连接长连地址。

4. 连接成功后先发送 `OP_AUTH` 包（Body 为 `auth_body` 原文），收到 `OP_AUTH_REPLY` 后推送 `room_status_changed`，状态栏变绿。

5. Rust 解析事件帧为 `DanmuEvent` / `GiftEvent` / `CaptainEvent` / `EnterEvent`；`Version=2` 的 Body 先用 zlib 解压，再按 Proto 递归解析。

6. 维持两条心跳：WS 心跳包（`OP_HEARTBEAT`，20–30 秒）与开放平台项目心跳（`/v2/app/heartbeat`，20 秒）。

7. 经敏感词、黑名单、身份识别过滤后推送前端。

8. 前端展示并写入 `t_event_log`。

9. 断网自动重连**不设次数上限**，间隔按 5 秒 → 10 秒 → 30 秒退避（30 秒封顶），期间缓存事件；房间未开播时同样保持守候，开播后由 `LIVE_START` 触发录制。`wss_link` 返回多个集群地址时按顺序兜底切换。

10. 用户断开时调用 `/v2/app/end` 关闭场次，并清理连接资源。

11. 连接成功后可选「记住身份码」：身份码保存在本机，下次启动自动恢复长连，无需再次输入或点击。恢复后保持守候，开播时由 `LIVE_START` 自动刷新直播状态并触发已配置的功能（自动录制、提醒、播报等）。关闭该开关即删除本机保存的身份码。

> 说明：连接凭据只能是主播身份码（开放平台 `code`），房间号不具备鉴权能力，仅用于展示、录制与数据归属。

#### 9.1.1 事件命令（CMD）清单

长连推送的消息体形如 `{"cmd":"...","data":{...}}`；`Version=2` 时先 zlib 解压再按 Proto 递归解析。官方开放文档列出的全部命令与处理要求：

| CMD | 含义 | 处理要求 |
| --- | --- | --- |
| `LIVE_OPEN_PLATFORM_DM` | 弹幕 | 采集为弹幕事件，携带 `uname` / `uid` / `open_id` / 粉丝勋章 / 舰队等级 / 房管标记 |
| `LIVE_OPEN_PLATFORM_DM_MIRROR` | 弹幕镜像（不显示发送人信息） | **忽略**：与 `DM` 重复且缺发送人字段，采集会造成重复计数 |
| `LIVE_OPEN_PLATFORM_SEND_GIFT` | 礼物 | 采集为礼物事件，金额 = `price × gift_num ÷ 10`（分），并绑定礼物音效与提醒 |
| `LIVE_OPEN_PLATFORM_SUPER_CHAT` | 醒目留言 | 采集为醒目留言事件：保留留言文本、金额与时长，计入营收并在弹幕面板高亮 |
| `LIVE_OPEN_PLATFORM_SUPER_CHAT_DEL` | 醒目留言撤回 | 按 `message_id` 撤回对应留言的展示，不删除已产生的统计数据 |
| `LIVE_OPEN_PLATFORM_GUARD` | 上舰（开通 / 续费） | 采集为舰长事件，映射 `guard_level` 1/2/3 → 总督 / 提督 / 舰长，触发上舰特效 |
| `LIVE_OPEN_PLATFORM_LIKE` | 点赞 | 汇总为互动计数，不逐条展示 |
| `LIVE_OPEN_PLATFORM_LIVE_ROOM_ENTER` | 进入直播间 | 采集为进入事件，用于在线人数与新增关注面板 |
| `LIVE_OPEN_PLATFORM_LIVE_START` | 直播开始 | 标记场次开始：重置本场统计，允许自动开录 |
| `LIVE_OPEN_PLATFORM_LIVE_END` | 直播结束 | 标记场次结束：停止自动录制、封存本场统计 |
| `LIVE_OPEN_PLATFORM_INTERACTION_END` | 互动玩法结束（心跳过期或主动 END） | 视为连接失效：按断线流程进入重连，不静默吞掉 |

验收标准：弹幕接收延迟＜100ms；连接成功率＞99%；自动重连成功率＞95%；支持 1000 条 / 秒高并发；不产生任何发送弹幕或处置用户的请求。

### 9.13 AI 语音回复模块

#### 9.13.1 功能描述

内置功能。对过滤后的观众弹幕按规则触发大模型生成回复文本，结果在工具内显示；并通过本地 TTS 播报到用户指定音频设备，由 Bilibili 直播姬 / OBS 采集后输出给观众听到。整合自定义人设、上下文记忆、内容过滤、AI 语音回复队列、模型配置与 TTS 音频路由。

**核心边界**：



* **不发送弹幕、不调用直播间发送接口、不提供发送按钮或发送 Command**。

* AI 语音回复默认关闭，需用户显式开启并完成音频路由确认。

* 软件本身不内置 AI 文本生成模型，不捆绑任何模型权重。

* 未配置 AI 模型时，AI 语音回复不可开启。

* AI 生成文本必须符合人与人即时聊天的风格：短句、口语化、一次只回应一个点，不写成段子、不写成文章、不写成客服话术。

#### 9.13.2 业务流程



1. 用户安装应用，AI 语音回复功能默认可用（需自行配置模型）。

2. 用户在 "AI 模型配置" 中单独配置 LLM：选择 Provider 或自定义 OpenAI 兼容端点，填写 Base URL、API Key、模型名、温度、最大长度等。软件不内置模型，未配置模型时 AI 语音回复不可开启。

3. 用户可配置多个模型档案，指定其中一个为 AI 语音回复默认模型。

4. 用户可点击 "测试连接"，Rust 发起一次轻量请求校验 Base URL、API Key、模型名是否可用。

5. 用户配置 AI 人设、说话风格、系统提示词、敏感词、上下文窗口。

6. 用户配置 AI 语音回复规则：触发范围、频率限制、冷却时间、最大长度、聊天风格档位、TTS 模板。

7. 用户选择 TTS 输出设备。推荐虚拟音频设备，如 Windows VB-CABLE、macOS BlackHole、Linux PulseAudio null sink。

8. 用户点击 "测试播报"，确认 OBS / 直播姬对应音频源有电平。

9. 用户显式开启 "AI 语音回复"，首次开启弹出确认弹窗并完成音频路由确认。

10. 观众发送弹幕，Rust 经敏感词、黑名单、身份过滤后进入 AI 语音回复判定。

11. 命中触发规则后进入 AI 语音回复队列，Rust 组装上下文并调用用户配置的外部 LLM。

12. LLM 流式返回，前端通过 `ai_generation_delta` 展示生成过程。

13. 生成完成后执行敏感词过滤、即时聊天风格校验、长度截断、重复检测。

14. 结果写入 AI 语音回复队列并显示在软件内。

15. AI 语音回复开启后，结果自动进入 TTS 播报队列，按优先级和冷却规则播报到指定音频设备。

16. OBS / 直播姬采集该音频设备输出给观众。

17. 用户可暂停 AI 语音回复、暂停 / 跳过当前播报、清空队列、重新生成、复制文本。

18. 写入 `t_ai_log` 与播报日志，不记录发送状态（本功能不存在发送动作）。

#### 9.13.4 即时聊天风格约束

**生成目标**

AI 回复应模拟真人在直播间弹幕里即时聊天的语气，而不是写文案、写总结、写客服回复。



| 维度 | 要求                                   |
| -- | ------------------------------------ |
| 长度 | 默认 ≤50 字；打招呼 / 简单问题 ≤20 字；复杂问题 ≤80 字 |
| 句数 | 默认 1-2 句，最多 3 句                      |
| 语气 | 口语化、自然、可直接朗读                         |
| 结构 | 单段纯文本，禁止分点、编号、标题、Markdown            |
| 开场 | 不写 "您好"" 感谢提问 ""作为 AI" 等客套或自指        |
| 内容 | 只回应一个核心点，不扩展成科普或长解释                  |
| 重复 | 不复述观众原话，不重复上一轮回复                     |
| 标点 | 少用感叹号堆叠，避免书面长句和括号注释                  |

**内置系统提示词约束**

Rust 侧在组装请求时，强制追加以下系统约束，用户人设提示词不得覆盖：



```
你必须像真人在直播间即时聊天一样回复：
1. 用口语短句，默认不超过 50 个字，最多 2 句话。
2. 只回应对方这句话的一个核心点，不要展开成长篇解释。
3. 不要分点、不要编号、不要标题、不要 Markdown、不要总结。
4. 不要客套开场，不要说"作为 AI""以下是""希望对你有帮助"。
5. 不要复述对方原话，不要重复你上一句。
6. 输出纯文本，适合直接朗读。
```

**风格档位**



| 档位     | 默认最大长度 | 适用场景      |
| ------ | ------ | --------- |
| 极简     | 20 字   | 高频弹幕、挂机直播 |
| 自然（默认） | 50 字   | 日常直播互动    |
| 稍详细    | 80 字   | 解答具体问题    |

> 无论哪档，都禁止分点列表和长文；超过上限由 Rust 侧硬截断。

**生成后处理**



1. Rust 对 LLM 返回文本执行长度截断。

2. 检测到分点、编号、标题、Markdown 标记时，降级为纯文本或重新生成一次。

3. 检测到客套开场、AI 自指、复述原话时，剥离或重新生成。

4. 截断后仍超长，丢弃并记录失败，不播报。

5. TTS 播报前再次检查长度，超长不播报。

**正反例**



| 观众弹幕    | 推荐回复         | 不推荐回复                            |
| ------- | ------------ | -------------------------------- |
| 今天直播真不错 | 谢谢呀，今天状态挺好～  | 非常感谢您的支持！您的认可是我最大的动力，我会继续努力……    |
| 求个歌单    | 歌单在主页置顶，去看看吧 | 关于歌单，我为您整理了以下内容：1.……2.……3.……     |
| 主播吃饭了吗  | 刚吃完，你呢       | 您好，感谢您的关心。作为 AI 助手，我无法进食，但主播本人…… |
| 这个怎么过   | 先往左跳，再二段跳    | 这个关卡的通关方法可以从以下几个方面来分析：第一…… 第二……  |

**验收标准**



1. 默认档位下，≥80% 的 AI 回复不超过 50 字。

2. 输出中不出现分点列表、编号、标题、Markdown。

3. 输出中不出现 "作为 AI"" 以下是 ""希望对你有帮助" 等表述。

4. 超长文本被截断或丢弃，不进入 TTS 播报。

5. TTS 播报文本与界面显示文本一致。

6. 风格档位切换后，长度上限立即生效。

7. 即时聊天风格约束不可被用户人设提示词覆盖。

#### 9.13.10 验收标准



1. AI 语音回复默认关闭，开启需显式确认并完成音频路由确认。

2. 未配置 AI 模型时，AI 语音回复不可开启。

3. 软件安装包不包含任何 LLM 模型权重。

4. 支持国内外云模型、第三方聚合 API、本地模型服务、自定义 OpenAI 兼容端点。

5. 支持多模型档案与默认模型切换；API Key 加密存储，请求由 Rust 发起。

6. 弹幕触发到 AI 文本显示 ≤5 秒；文本完成到 TTS 开始 ≤500ms；端到端输出 ≤6 秒，不含 OBS 采集缓冲。

7. 默认档位下 ≥80% 回复 ≤50 字；输出不含分点、编号、标题、Markdown；不含客套开场与 AI 自指。

8. 超长文本截断或丢弃，不进入 TTS；TTS 播报文本与界面显示一致。

9. 支持选择 TTS 输出设备，测试播报在 OBS / 直播姬可见电平。

10. 支持全局冷却、单用户冷却、队列上限、触发范围配置。

11. 只有一个 "AI 语音回复" 总开关，不设独立 "语音播报" 开关；开启后生成与播报同时生效，关闭后同时停止。

12. 保留暂停播报、跳过当前、清空队列等运行时控制。

13. AI 结果只在工具内显示，语音只输出到本地音频设备。

14. 不存在发送弹幕按钮、Command 或自动任务。

15. 设备丢失、LLM 失败、队列溢出、TTS 引擎不可用均有降级处理。

## 11. IPC 安全与参数校验

### 11.1 设计原则



* 所有 Tauri Command 在 Rust 侧做参数校验、类型校验、范围校验、路径白名单。

* 前端不直接访问文件系统、数据库、密钥。

* 文件操作强制走系统文件对话框，禁止前端传入任意本地路径。

* 特效窗口独立 Capability，不授予任何 IPC 命令。

* **不注册任何&#x20;**`danmu_send`**、**`reply_send`**、**`mute`**、**`kick`**&#x20;类 Command。**

### 11.2 校验规则



| 参数类型      | 校验规则                      |
| --------- | ------------------------- |
| 房间号       | 数字字符串，长度 1-20             |
| 用户名       | 长度 1-50，去除控制字符            |
| 文件路径      | 仅允许系统对话框返回的路径，禁止前端拼接      |
| 音量        | 0-1 浮点                    |
| 阈值        | 非负整数                      |
| 时间范围      | 枚举值                       |
| 敏感词       | 长度 1-100，去除控制字符           |
| 模板        | 变量名白名单校验                  |
| 模型档案 ID   | 白名单枚举                     |
| Base URL  | 协议 http/https，长度限制，禁止非法字符 |
| API Key   | 非空，长度限制，加密存储              |
| TTS 设备 ID | Rust 枚举白名单                |
| 聊天风格档位    | 枚举：极简 / 自然 / 稍详细          |

### 11.3 路径白名单



* 录制目录、导出目录由用户在设置中选择，存入配置。

* IPC 命令只接受配置中的路径，不接受前端传入的任意路径。

* 文件选择通过 `tauri-plugin-dialog` 完成，返回路径由 Rust 校验后使用。

* 模型档案与 API Key 存储路径由 Rust 管理，前端不可指定。

## 12. 隐私、数据留存与合规

### 12.1 数据本地化



* 监听记录、统计数据、黑名单、敏感词、AI 日志、录制文件默认仅存储在本机，不上传。

* 运行日志仅写入本地文件；不内置崩溃上报、行为埋点上报；后续如新增任何上报，必须提供独立默认关闭的开关并明示范围。

### 12.2 外部 LLM 数据范围



* 仅当用户主动配置并开启 AI 语音回复时，才向用户指定的 LLM 端点发送组装后的上下文，可能包含：触发弹幕文本、观众昵称与身份标签、AI 人设提示词、近期对话上下文。

* 首次开启前，确认弹窗需明示 "将向所配置模型端点发送弹幕文本与昵称身份信息"。

* API Key 仅保存在本机加密存储，不写入运行日志，不出现在导出文件明文；导出配置时 API Key 默认脱敏，用户可选择是否随导出文件保留。

### 12.3 数据保留默认策略



| 数据类型       | 默认保留期 | 可选保留期                    | 清理方式          |
| ---------- | ----- | ------------------------ | ------------- |
| 事件日志       | 90 天  | 7 / 30 / 90 / 180 天 / 永久 | 本地定时任务清理，可先导出 |
| AI 生成与播报日志 | 30 天  | 7 / 30 / 90 天 / 永久       | 同上            |
| 统计聚合数据     | 180 天 | 30 / 90 / 180 / 永久       | 同上            |
| 录制文件       | 不自动清理 | 由用户管理；受磁盘配额保护            | 达到水位提示清理或停止写入 |
| 运行日志       | 30 天  | 按级别与日期滚动                 | 自动滚动删除        |

### 12.4 数据清空



* 设置页提供 "清空本地数据" 入口，可选择清空：事件日志、AI 日志、缓存、全部应用数据（含配置与模型档案）。

* 清空操作二次确认；涉及 API Key、模型档案删除时不可恢复。

### 12.5 合规边界



* 应用不发送弹幕、不回复公屏消息、不处置直播间用户；AI 语音回复仅通过本地音频设备输出，由主播自行决定是否接入直播流。

* 录制功能仅用于本人或已获授权直播间的存档与二创；用户应自行遵守平台规则与版权要求。

* 应用不对 LLM 生成内容的合规性作担保；输出侧保留敏感词过滤与风格后处理，主播应对播出内容负最终责任。

## 14. 错误码分类



| 分类前缀       | 覆盖范围       | 典型场景                    |
| ---------- | ---------- | ----------------------- |
| `ROOM`     | 房间连接、断连、重连 | 身份码非法、连接失败、开放平台凭证失效     |
| `NET`      | 网络与外部端点    | 网络不可达、超时、DNS 失败         |
| `RULE`     | 敏感词、黑名单    | 词非法、导入结构错误、重复条目         |
| `GIFT`     | 礼物绑定与音效    | 礼物未绑定、音效文件缺失、音量越界       |
| `RECORD`   | 录制与高光      | 无可用流、FFmpeg 启动失败、磁盘配额耗尽 |
| `TTS`      | 弹幕播报与音频设备  | 引擎不可用、设备丢失、队列异常         |
| `AI_MODEL` | 模型档案与连接测试  | 未配置、Key 无效、模型不存在、协议不兼容  |
| `AI_GEN`   | AI 生成与后处理  | 超时、限流、格式不合格、重复拦截        |
| `AUDIO`    | 音频设备枚举与路由  | 设备列表为空、设备 ID 非法         |
| `CONFIG`   | 配置导入导出与迁移  | 结构校验失败、事务回滚、版本不兼容       |
| `STORAGE`  | 文件与数据库     | 目录不可写、数据库损坏、空间不足        |
| `UPDATE`   | 版本更新       | 包签名失败、版本黑名单、回滚          |
| `SYS`      | 系统级兜底      | 未知内部错误                  |

> 错误码统一为大写 `PREFIX_SEMANTIC` 形式（例 `ROOM_INVALID_ID`），前端按前缀聚合分类；原始错误详情仅写入本地日志，不在界面暴露内部堆栈。

## 15. 修订摘要
