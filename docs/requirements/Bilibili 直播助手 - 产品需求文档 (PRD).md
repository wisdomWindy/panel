# Bilibili 直播助手 Tauri 重构后 产品需求文档（PRD）

**创建日期**：2026-09-14  
**文档状态**：最终定稿（AI 语音回复归免费功能修订版）  
**重构目标**：将原 Bilibili 直播助手重构为 **Tauri 框架 + Rust 核心 + 前端 WebView + Sidecar** 的桌面应用  
**合规边界**：工具仍为直播间只读监听、本地提醒、本地录制、本地 AI 文本生成与本地语音输出；**不提供任何自动或手动发送弹幕能力**。

---

## 0. 关键前提

1. **只读监听**：B 站直播间事件仅做只读接收，不设计任何发送弹幕命令、按钮或自动任务。
2. **两个安装包**：产品分为 **免费版安装包** 和 **会员版安装包**，是两个独立发布的应用。
3. **免费版安装包**：包含全部免费版功能，**AI 语音回复属于免费功能**。免费版**没有任何充值入口、没有任何会员引导、没有任何会员功能入口**。
4. **会员版安装包**：默认只显示免费版功能（含 AI 语音回复），**有会员充值入口**；用户充值成功后，下载并启用会员功能模块（自动禁言与刷屏防护）。
5. **会员登录**：会员版安装包通过 **B 站扫码登录** 完成身份绑定，Rust 端直接调用社区维护的扫码登录 API，不经过自建后端。保留「手动输入 UID」作为降级方案。
6. **到期暂停、续费恢复**：会员到期后，**自动禁言与刷屏防护暂停**，已下载模块保留；续费后无需重新下载，直接恢复。**AI 语音回复为免费功能，不因会员到期而暂停**。
7. **Sidecar 合规**：FFmpeg 使用现成 LGPL 预编译构建，随主包分发；whisper.cpp 作为免费可选 AI 组件按需下载；whisper 模型按需下载。
8. **本地优先**：监听、过滤、统计、录制、AI 生成与语音输出均以本地为主，默认不上传用户数据。
9. **数据统计与展示为两个安装包共有底座**：数据看板、排行榜、数据导出、历史查询、数据保留策略，免费版与会员版一致，不因会员状态而裁剪。
10. **AI 文本生成模型不内置**：软件本身不内置、不捆绑任何 LLM 模型权重。AI 文本生成模型由用户单独配置，支持国内外主流模型、第三方聚合 API、本地模型服务和自定义 OpenAI 兼容端点。
11. **AI 语音回复为免费功能且不发送弹幕**：AI 语音回复包含“按规则生成回复文本 + 软件内显示 + 本地 TTS 播报到指定音频设备”。语音由 Bilibili 直播姬/OBS 采集后输出给观众听到。**不调用 B 站发送弹幕接口，不提供发送按钮或发送 Command**。AI 语音回复默认关闭，需用户显式开启并完成音频路由确认。

## 1. 产品概述

### 1.1 产品愿景

打造一款集观众弹幕监控、智能观测、特效展示、直播录制、数据分析于一体的 Bilibili 直播辅助工具，帮助主播降低直播运营成本，实时掌握直播间观众互动情况，同时满足内容存档和二次创作需求。

产品以两个独立安装包交付，通过会员体系区分能力：

1. **免费版安装包**：纯直播间只读数据监听、本地提醒、数据统计、风控管理（不含自动禁言）、弹幕语音播报、直播录制、多语言、基础 UI，以及 **AI 语音回复**（需用户自行配置外部 LLM 模型）。**无任何充值入口，无任何会员引导，无任何自动发送弹幕能力**。
2. **会员版安装包**：默认显示免费版全部功能（含 AI 语音回复），提供会员充值入口。用户充值成功后，自动下载会员功能模块并启用，增加 **自动禁言与刷屏防护**。

### 1.2 目标用户

- Bilibili 全职/兼职游戏、娱乐、虚拟主播
- 直播间运营团队成员，负责直播复盘、互动运营
- 需要 24 小时无人值守挂机监控、维持直播间基础互动的虚拟主播、挂机直播间运营者

## 2. 重构概述

### 2.1 重构背景

原产品功能覆盖弹幕监听、风控、提醒、TTS、录制、AI 文案辅助等模块。为降低内存占用、提升并发性能、增强安全隔离和跨平台发布，决定采用 Tauri 框架重构。

Tauri 的核心优势：

- Rust 后端处理 WebSocket、规则引擎、录制、AI 调用、数据库等高负载任务。
- WebView 前端只负责 UI 渲染，降低内存占用。
- 通过 IPC Command / Event 实现前后端解耦。
- 通过 Capabilities 权限系统限制前端能力。
- 支持 Sidecar 集成 ffmpeg、whisper.cpp 等本地二进制。
- 支持自动更新、系统托盘、全局快捷键、通知、多窗口透明特效。

### 2.2 重构目标

1. 保持原产品全部免费/会员功能，产品体验不降级。
2. 核心能力 Rust 化：WebSocket、敏感词、刷屏检测、录制控制、TTS 队列、AI 调用、数据库、扫码登录。
3. 前端轻量化：仅通过 `invoke` 和 `listen` 与 Rust 交互，不直接访问文件系统、数据库和密钥。
4. 安全增强：所有 IPC 命令在 Rust 侧做参数校验、类型校验、路径白名单。
5. 性能提升：空闲内存 ≤120MB，录制+AI 模式内存 ≤200MB，CPU 增量 ≤15%。
6. 发布现代化：双安装包、应用内会员、模块按需下载、多通道更新、灰度发布、签名校验、回滚。

### 2.3 重构原则

- **本地优先**：监听、过滤、统计、录制、AI 生成、TTS 输出、扫码登录均以本地为主。
- **只读监听**：B 站 WebSocket 仅接收事件，不设计发送弹幕命令。
- **权限最小化**：Tauri Capabilities 按窗口分配权限，IPC 命令在 Rust 侧二次校验。
- **模块解耦**：AI 异常不影响监听、提醒、统计和录制。
- **数据兼容**：历史配置、日志、统计可迁移，迁移失败自动回滚。
- **可观测**：Rust `tracing` + 前端日志面板 + 本地日志文件 + 业务埋点。
- **底座一致**：数据统计与展示为两个安装包共有，不因会员状态而裁剪。
- **免费版零付费干扰**：免费版安装包不出现任何充值、会员、升级引导。
- **AI 语音回复免费**：AI 语音回复、AI 模型配置、TTS 音频路由为免费功能，两个安装包均包含。
- **会员功能可下载、可暂停、可恢复**：会员功能模块独立于主包，按需下载，到期暂停，续费恢复。
- **登录不留服务端**：B 站扫码登录完全在应用内 Rust 侧完成，不依赖自建后端。
- **AI 模型不内置**：软件不捆绑任何 LLM 权重，由用户自行配置外部模型或本地模型服务。
- **AI 语音回复即时聊天化**：AI 生成文本必须短句、口语化、纯文本单段，禁止长文、分点、标题、Markdown、客套开场和 AI 自指。
- **AI 不发送弹幕**：AI 语音回复只生成文本、本地显示、本地 TTS 输出，不调用直播间发送接口。

## 4. 版本策略与用户群体

### 4.1 双安装包矩阵

| 安装包       | 面向用户           | 默认功能                     | 充值入口 | 登录入口 | 会员模块下载               |
| ------------ | ------------------ | ---------------------------- | -------- | -------- | -------------------------- |
| 免费版安装包 | 所有用户           | 免费版功能（含 AI 语音回复） | 无       | 无       | 无                         |
| 会员版安装包 | 需要自动禁言的用户 | 免费版功能（含 AI 语音回复） | 有       | 有       | 充值成功后下载自动禁言模块 |

### 4.2 免费版安装包行为

- 显示免费版全部功能入口，包括 AI 助手。
- **包含 AI 语音回复、AI 模型配置、TTS 音频路由、可选 whisper 组件下载**。
- 不显示会员中心、刷屏防护入口。
- 不显示任何登录、升级引导、会员广告、充值按钮。
- 不包含会员模块下载能力。
- 不包含会员鉴权逻辑。
- 不包含 B 站扫码登录逻辑。
- 不包含自动禁言与刷屏防护。
- 用户完全感知不到会员体系与登录体系的存在。

### 4.3 会员版安装包行为

- 默认显示免费版全部功能，包括 AI 语音回复。
- 顶部工具栏显示「登录 / 开通会员」按钮。
- 左侧导航显示「会员中心」入口。
- 不显示刷屏防护入口（未充值前）。
- 用户登录后，可查看套餐并充值。
- 充值成功后：
  - 自动下载自动禁言模块、会员中心模块。
  - 下载完成后显示刷屏防护入口。
  - 顶部工具栏显示会员到期时间。
- 会员到期后：
  - 刷屏防护入口置灰。
  - 顶部工具栏显示「续费」。
  - 已下载模块保留。
  - **AI 语音回复不受影响，继续可用**。
  - 续费后自动禁言立即恢复。

### 4.4 共有底座能力

| 能力           | 说明                                                         |
| -------------- | ------------------------------------------------------------ |
| 实时数据看板   | 在线人数、弹幕量、弹幕速率、礼物收益、舰长数据及趋势曲线     |
| 排行榜         | 送礼榜、弹幕互动榜、舰长贡献榜，实时更新                     |
| 数据导出       | 看板数据、榜单数据导出 CSV                                   |
| 历史数据查询   | 按时间范围查询历史统计                                       |
| 数据保留与清理 | 统一保留策略，两个版本一致                                   |
| AI 语音回复    | 生成回复文本、软件内显示、本地 TTS 播报、模型配置、音频路由，两个版本一致 |

### 4.5 数据目录策略

- 两个安装包使用相同应用标识符与数据目录。
- 免费版安装包升级到会员版安装包：覆盖安装，数据保留。
- 会员版安装包降级到免费版安装包：提示会员模块与登录信息将不可用，建议先导出配置；AI 语音回复配置与模型档案保留。
- 会员模块存放在 `modules/` 子目录，与主包隔离。
- 登录信息存放在 `account.json`，与主包配置分离。
- AI 模型档案与 API Key 加密存储，与主包配置分离。
- 会员到期不删除模块，续费后直接复用。

## 5. 会员体系与模块策略

### 5.1 会员模型

| 状态         | 免费版安装包 | 会员版安装包                                              |
| ------------ | ------------ | --------------------------------------------------------- |
| 未登录       | 不适用       | 免费版功能可用（含 AI 语音回复）；显示登录/开通会员入口   |
| 已登录未付费 | 不适用       | 免费版功能可用（含 AI 语音回复）；显示套餐与充值入口      |
| 付费成功     | 不适用       | 自动下载并启用自动禁言模块；显示刷屏防护入口              |
| 会员到期     | 不适用       | 自动禁言暂停；刷屏防护置灰；AI 语音回复不受影响；显示续费 |
| 续费成功     | 不适用       | 无需重新下载；自动禁言立即恢复                            |

### 5.2 会员功能模块与免费 AI 组件

**会员功能模块**（仅会员版充值后下载）：

| 会员中心模块 | 会员中心页面、订单记录、续费入口                        | 前端资源包        |

**免费 AI 组件**（两个安装包均可按需下载）：

### 5.3 模块下载与安装流程

1. 用户在会员中心点击「开通会员」。
2. 前端调用 `membership_purchase(plan_id)`。
3. Rust 通过 `reqwest` 向服务端发起支付请求，返回支付二维码或支付链接。
4. 前端展示支付二维码，用户扫码支付。
5. Rust 轮询支付状态，成功后服务端返回：
   - 会员签名令牌（Ed25519 签名，含有效期）。
   - 模块清单（模块名、版本、下载地址、哈希）。
6. Rust 校验令牌签名，写入 `t_membership`。
7. Rust 依次下载会员模块包：
   - 下载到临时目录。
   - 校验哈希。
   - 解压到 `modules/<module_name>/<version>/`。
   - 写入 `t_module`。
8. 下载完成后推送 `module_installed` 事件。
9. 前端动态加载会员模块资源，显示刷屏防护入口。
10. 会员功能立即可用。

> AI 可选组件与 whisper 模型由用户独立下载，不属于会员付费流程。

### 5.4 到期暂停流程

1. Rust 每次启动、每小时定时、每次自动禁言调用前校验令牌有效期。
2. 令牌过期后：
   - Rust 停止自动禁言服务。
   - 推送 `membership_expired` 事件。
3. 前端：
   - 刷屏防护入口置灰。
   - 显示续费引导。
   - 已下载模块保留，不删除。
   - **AI 语音回复、AI 模型配置、TTS 音频路由不受影响**。
4. 用户可继续使用全部免费版功能。

### 5.5 续费恢复流程

1. 用户在会员中心点击「续费」。
2. 重复 5.3 的支付流程。
3. 支付成功后服务端返回新令牌。
4. Rust 校验签名，更新 `t_membership`。
5. 若自动禁言模块已下载且版本一致，跳过下载，直接加载。
6. 若模块有新版本，按 5.3 流程更新。
7. 推送 `membership_renewed` 事件。
8. 前端恢复刷屏防护入口，Rust 重启自动禁言服务。

### 5.6 会员鉴权

| 项目       | 说明                                                 |
| ---------- | ---------------------------------------------------- |
| 签名算法   | Ed25519                                              |
| 公钥位置   | 硬编码在会员版 Rust 二进制，不存数据库；免费版不包含 |
| 令牌内容   | 用户 UID、会员等级、有效期、签发时间、随机数         |
| 校验位置   | Rust 侧，前端无法拿到校验结果原文                    |
| 本地存储   | `t_membership` 加密存储，字段带签名                  |
| 防篡改     | 修改数据库字段导致签名失效，会员状态失效             |
| 离线有效期 | 默认 7 天，超时必须联网校验                          |
| 联网校验   | 每日一次心跳，异常时降级为离线有效期                 |
| 令牌刷新   | 有效期内自动刷新，避免频繁登录                       |

#### 场景 7：AI 语音回复生成与播报（免费功能）

1. 主播配置外部 LLM 模型档案、AI 人设、触发规则、敏感词和上下文范围。
2. 主播选择 TTS 输出设备，推荐虚拟音频设备，并在 OBS/直播姬中添加对应音频源。
3. 主播点击测试播报，确认 OBS/直播姬可见电平。
4. 主播显式开启「AI 语音回复」，首次开启完成音频路由确认。
5. 观众发送弹幕后，Rust 经敏感词、黑名单、身份过滤后判断是否触发。
6. 触发的弹幕进入 AI 语音回复队列，Rust 组装上下文调用外部 LLM。
7. AI 生成即时聊天风格的短句回复，经敏感词过滤、长度截断后显示在软件内。
8. 回复文本自动进入 TTS 播报队列，按优先级和冷却规则播报到指定音频设备。
9. OBS/直播姬采集该音频设备，观众听到 AI 回复语音。
10. 主播可随时暂停 AI 语音回复、暂停/跳过当前播报、清空队列、重新生成或复制文本。
11. 全程不产生任何发送弹幕请求。

1. 系统实时监测直播间弹幕热度、礼物波动数据。

3. 自动录制高光前后 30 秒片段，独立保存为 MP4 文件。
4. 主播也可通过 F9 快捷键手动标记高光时刻。
5. 直播结束后，主播可手动剪辑、上传高光片段至 B 站。

3. 本地日志记录感谢文案，仅工具内展示，不对外发送弹幕。
4. 特效停留 5 秒后自动淡出，不影响直播画面。

#### 场景 10：全场直播存档录制（免费版功能）

4. 禁言结果写入日志，前端展示系统提示。
5. 接口不可用时自动降级为本地告警，由用户手动处理。

## 9. 功能详细需求

### 9.1 直播间连接与弹幕接收（免费）

通过 WebSocket 全量连接 Bilibili 直播间，实时接收观众弹幕流、直播间各类事件流，毫秒级同步展示在本地面板，**仅做只读接收，无任何主动发送、操作直播间权限**。

关键流程：

1. 用户选择房间并点击「连接」。
2. 前端调用 `room_connect(room_id)`，Rust 校验房间号格式。
3. Rust 请求房间初始化信息，建立 WebSocket 长连接。
4. 连接成功后推送 `room_status_changed`，状态栏变绿。
5. Rust 解析事件帧为 `DanmuEvent` / `GiftEvent` / `CaptainEvent` / `EnterEvent`。
6. 经敏感词、黑名单、身份识别过滤后推送前端。
7. 前端展示并写入 `t_event_log`。
8. 断网自动重连，最多 10 次，间隔 5 秒，期间缓存事件。
9. 用户断开时关闭连接并清理资源。

验收标准：弹幕接收延迟＜100ms；连接成功率＞99%；自动重连成功率＞95%；支持 1000 条/秒高并发；不产生任何发送弹幕请求。

自动解析弹幕事件中的用户身份、粉丝等级、勋章信息，在弹幕面板以差异化颜色、标签区分。

| -------- | ------ | -------- |
| 房管     | [房管] | 绿色     |

| 提督     | [提督] | 蓝色     |
| 舰长     | [舰长] | 金色     |
| 老爷     | [老爷] | 橙色     |

### 9.3 敏感词过滤（免费）

内置分级敏感词库，支持自定义词汇，自动拦截违规、广告、引战弹幕，屏蔽展示与语音播报，完整留存过滤日志。

关键流程：

1. Rust 在弹幕进入 EventBus 前，先经敏感词引擎。
2. 使用 Aho-Corasick 匹配精确词，正则匹配模糊规则。
3. 命中后根据词类型决定处理：直接屏蔽 / 替换 / 仅记录。
4. 命中弹幕不进入前端展示、不进入 TTS 队列、不进入 AI 上下文。
5. 写入 `t_event_log`，标记 `filtered=true` 与命中词。
6. 用户在风控中心可查看、新增、删除、导入、导出词库。

验收标准：过滤准确率 100%，过滤延迟＜10ms，支持万级词库，误判率＜1%。

### 9.4 自动禁言与刷屏防护（会员）

基于频率、重复度、相似度规则识别刷屏违规用户。**仅在会员版安装包且会员激活时可用**，使用主播本地账号 Cookie 能力调用 B 站管理接口，不承诺可用性，接口变动随时下线。自动禁言默认关闭，首次启用需独立风险确认。会员到期后暂停。

规则默认值：

| 规则         | 默认值                    | 可调范围            |
| ------------ | ------------------------- | ------------------- |
| 频率违规     | 10 秒内＞5 条             | 可调                |
| 重复违规     | 1 分钟内＞3 条相同        | 可调                |
| 相似违规     | 1 分钟内＞5 条相似度＞80% | 可调                |
| 默认禁言时长 | 1 小时                    | 10 分钟/1 小时/永久 |

验收标准：刷屏检测准确率＞95%；禁言响应＜2 秒（接口可用且会员激活时）；执行成功率＞98%；误判率＜3%；默认关闭；会员到期后暂停，续费后恢复。

### 9.14 AI 语音回复模块（免费）

#### 9.14.1 功能描述

免费功能。对过滤后的观众弹幕按规则触发大模型生成回复文本，结果在工具内显示；并通过本地 TTS 播报到用户指定音频设备，由 Bilibili 直播姬/OBS 采集后输出给观众听到。整合离线 ASR、自定义人设、上下文记忆、内容过滤、AI 语音回复队列、AI 模型配置与 TTS 音频路由。

**核心边界**：

- **不发送弹幕、不调用直播间发送接口、不提供发送按钮或发送 Command**。
- AI 语音回复默认关闭，需用户显式开启并完成音频路由确认。
- 软件本身不内置 AI 文本生成模型，不捆绑任何模型权重。
- 未配置 AI 模型时，AI 语音回复不可开启。
- **AI 语音回复为免费功能，两个安装包均包含，不因会员状态而启用、停用或置灰**。
- AI 生成文本必须符合人与人即时聊天的风格：短句、口语化、一次只回应一个点，不写成段子、不写成文章、不写成客服话术。

#### 9.14.2 业务流程

1. 用户安装免费版或会员版，AI 语音回复功能默认可用（需自行配置模型）。
2. 用户在“AI 模型配置”中单独配置 LLM：选择 Provider 或自定义 OpenAI 兼容端点，填写 Base URL、API Key、模型名、温度、最大长度等。软件不内置模型，未配置模型时 AI 语音回复不可开启。
3. 用户可配置多个模型档案，指定其中一个为 AI 语音回复默认模型。
4. 用户可点击“测试连接”，Rust 发起一次轻量请求校验 Base URL、API Key、模型名是否可用。
5. 用户配置 AI 人设、说话风格、系统提示词、敏感词、上下文窗口。
6. 用户配置 AI 语音回复规则：触发范围、频率限制、冷却时间、最大长度、聊天风格档位、TTS 模板。
7. 用户选择 TTS 输出设备。推荐虚拟音频设备，如 Windows VB-CABLE、macOS BlackHole、Linux PulseAudio null sink。
8. 用户点击“测试播报”，确认 OBS/直播姬对应音频源有电平。
9. 用户显式开启“AI 语音回复”，首次开启弹出确认弹窗并完成音频路由确认。
10. 观众发送弹幕，Rust 经敏感词、黑名单、身份过滤后进入 AI 语音回复判定。
11. 命中触发规则后进入 AI 语音回复队列，Rust 组装上下文并调用用户配置的外部 LLM。
12. LLM 流式返回，前端通过 `ai_generation_delta` 展示生成过程。
13. 生成完成后执行敏感词过滤、即时聊天风格校验、长度截断、重复检测。
14. 结果写入 AI 语音回复队列并显示在软件内。
15. AI 语音回复开启后，结果自动进入 TTS 播报队列，按优先级和冷却规则播报到指定音频设备。
16. OBS/直播姬采集该音频设备输出给观众。
17. 用户可暂停 AI 语音回复、暂停/跳过当前播报、清空队列、重新生成、复制文本。
18. 写入 `t_ai_log` 与播报日志，不记录发送状态。

#### 9.14.4 即时聊天风格约束

**生成目标**

AI 回复应模拟真人在直播间弹幕里即时聊天的语气，而不是写文案、写总结、写客服回复。

| 维度 | 要求                                                 |
| ---- | ---------------------------------------------------- |
| 长度 | 默认 ≤50 字；打招呼/简单问题 ≤20 字；复杂问题 ≤80 字 |
| 句数 | 默认 1-2 句，最多 3 句                               |
| 语气 | 口语化、自然、可直接朗读                             |
| 结构 | 单段纯文本，禁止分点、编号、标题、Markdown           |
| 开场 | 不写“您好”“感谢提问”“作为 AI”等客套或自指            |
| 内容 | 只回应一个核心点，不扩展成科普或长解释               |
| 重复 | 不复述观众原话，不重复上一轮回复                     |
| 标点 | 少用感叹号堆叠，避免书面长句和括号注释               |

**内置系统提示词约束**

Rust 侧在组装请求时，强制追加以下系统约束，用户人设提示词不得覆盖：

```text
你必须像真人在直播间即时聊天一样回复：
1. 用口语短句，默认不超过 50 个字，最多 2 句话。
2. 只回应对方这句话的一个核心点，不要展开成长篇解释。
3. 不要分点、不要编号、不要标题、不要 Markdown、不要总结。
4. 不要客套开场，不要说“作为 AI”“以下是”“希望对你有帮助”。
5. 不要复述对方原话，不要重复你上一句。
6. 输出纯文本，适合直接朗读。
```

**风格档位**

| 档位         | 默认最大长度 | 适用场景           |
| ------------ | ------------ | ------------------ |
| 极简         | 20 字        | 高频弹幕、挂机直播 |
| 自然（默认） | 50 字        | 日常直播互动       |
| 稍详细       | 80 字        | 解答具体问题       |

> 无论哪档，都禁止分点列表和长文；超过上限由 Rust 侧硬截断。

**生成后处理**

1. Rust 对 LLM 返回文本执行长度截断。
2. 检测到分点、编号、标题、Markdown 标记时，降级为纯文本或重新生成一次。
3. 检测到客套开场、AI 自指、复述原话时，剥离或重新生成。
4. 截断后仍超长，丢弃并记录失败，不播报。
5. TTS 播报前再次检查长度，超长不播报。

**正反例**

| 观众弹幕       | 推荐回复                 | 不推荐回复                                                 |
| -------------- | ------------------------ | ---------------------------------------------------------- |
| 今天直播真不错 | 谢谢呀，今天状态挺好～   | 非常感谢您的支持！您的认可是我最大的动力，我会继续努力……   |
| 求个歌单       | 歌单在主页置顶，去看看吧 | 关于歌单，我为您整理了以下内容：1.……2.……3.……               |
| 主播吃饭了吗   | 刚吃完，你呢             | 您好，感谢您的关心。作为 AI 助手，我无法进食，但主播本人…… |
| 这个怎么过     | 先往左跳，再二段跳       | 这个关卡的通关方法可以从以下几个方面来分析：第一……第二……   |

**验收标准**

1. 默认档位下，≥80% 的 AI 回复不超过 50 字。
2. 输出中不出现分点列表、编号、标题、Markdown。
3. 输出中不出现“作为 AI”“以下是”“希望对你有帮助”等表述。
4. 超长文本被截断或丢弃，不进入 TTS 播报。
5. TTS 播报文本与界面显示文本一致。
6. 风格档位切换后，长度上限立即生效。
7. 即时聊天风格约束不可被用户人设提示词覆盖。

#### 9.14.10 验收标准

1. AI 语音回复默认关闭，开启需显式确认并完成音频路由确认。
2. 未配置 AI 模型时，AI 语音回复不可开启。
3. 软件安装包不包含任何 LLM 模型权重。
4. 支持国内外云模型、第三方聚合 API、本地模型服务、自定义 OpenAI 兼容端点。
5. 支持多模型档案与默认模型切换；API Key 加密存储，请求由 Rust 发起。
6. 弹幕触发到 AI 文本显示 ≤5 秒；文本完成到 TTS 开始 ≤500ms；端到端输出 ≤6 秒，不含 OBS 采集缓冲。
7. 默认档位下 ≥80% 回复 ≤50 字；输出不含分点、编号、标题、Markdown；不含客套开场与 AI 自指。
8. 超长文本截断或丢弃，不进入 TTS；TTS 播报文本与界面显示一致。
9. 支持选择 TTS 输出设备，测试播报在 OBS/直播姬可见电平。
10. 支持全局冷却、单用户冷却、队列上限、触发范围配置。
11. 只有一个“AI 语音回复”总开关，不设独立“语音播报”开关；开启后生成与播报同时生效，关闭后同时停止。
12. 保留暂停播报、跳过当前、清空队列等运行时控制。
13. AI 结果只在工具内显示，语音只输出到本地音频设备。
14. 不存在发送弹幕按钮、Command 或自动任务。
15. **免费版安装包与会员版安装包均包含 AI 语音回复、AI 模型配置、TTS 音频路由命令**。
16. **会员到期不影响 AI 语音回复，AI 语音回复继续可用**。
17. 设备丢失、LLM 失败、队列溢出均有降级处理。
18. whisper.cpp 与 whisper 模型为可选下载，缺失时仅影响 ASR，不影响文本生成与 TTS。

### 9.15 B 站扫码登录（会员版专属）

会员版安装包专属。通过 B 站扫码登录完成身份绑定，Rust 端直接调用社区维护的扫码登录 API，不经过自建后端。登录成功后提取 `DedeUserID`（B 站 UID）作为用户唯一标识，用于会员绑定。保留「手动输入 UID」作为降级方案。

关键实现要点：

- 每个登录会话使用独立 `reqwest::Client`，开启 `cookie_store(true)`。
- 登录成功后，Cookie 仅保存在内存；只把 UID、昵称、头像写入 `account.json`。
- 轮询在 Rust 侧异步任务完成，前端只接收 `auth_qrcode_status` 事件。
- 二维码由 Rust 用 `qrcode` crate 将 url 渲染为 PNG，base64 编码后传前端。
- 轮询连续失败 5 次才报错；正常每 2 秒一次，二维码有效期 180 秒。
- 扫码不可用时提供手动输入 UID 入口。

验收标准：扫码后 30 秒内登录成功；展示昵称、头像、UID；扫码不可用时提供 UID 输入入口；登录信息写入 `account.json`；Cookie 不落盘；连续轮询失败 5 次后报错；二维码失效后可刷新；免费版安装包不包含此功能。

## 10. IPC 安全与参数校验

### 10.1 设计原则

- 所有 Tauri Command 在 Rust 侧做参数校验、类型校验、范围校验、路径白名单。
- 前端不直接访问文件系统、数据库、密钥。
- 文件操作强制走系统文件对话框，禁止前端传入任意本地路径。
- 特效窗口独立 Capability，不授予任何 IPC 命令。
- AI 模型配置、AI 语音回复、TTS 音频路由相关 Command 在免费版和会员版均注册。
- 会员相关 Command 在会员版 Rust 侧额外校验会员状态；免费版不注册这些 Command。
- 登录相关 Command 在会员版 Rust 侧注册；免费版不注册。
- **不注册任何 `danmu_send`、`reply_send` 类 Command。**

### 10.2 校验规则

| 参数类型     | 校验规则                                 |
| ------------ | ---------------------------------------- |
| 房间号       | 数字字符串，长度 1-20                    |
| UID          | 数字字符串，长度 1-20                    |
| 用户名       | 长度 1-50，去除控制字符                  |
| 文件路径     | 仅允许系统对话框返回的路径，禁止前端拼接 |

| 阈值         | 非负整数                                 |
| 时间范围     | 枚举值                                   |
| 敏感词       | 长度 1-100，去除控制字符                 |
| 模板         | 变量名白名单校验                         |
| 套餐 ID      | 白名单枚举                               |
| 模块名       | 白名单枚举                               |

- AI 模型档案与 API Key 存储路径由 Rust 管理，前端不可指定。
