# Bilibili 直播助手 Tauri 重构后 产品需求文档（PRD）

**创建日期**：2026-09-14  
**文档状态**：最终定稿  
**重构目标**：将原 Bilibili 直播助手重构为 **Tauri 框架 + Rust 核心 + 前端 WebView + Sidecar** 的桌面应用  
**合规边界**：工具仍为直播间只读监听、本地提醒、本地录制、本地 AI 文案预览；**不提供任何自动或手动发送弹幕能力**。

---

## 0. 关键前提

本 PRD 基于以下前提，所有功能、架构、合规、分发策略均以此为准：

1. **只读监听**：B 站直播间事件仅做只读接收，不设计任何发送弹幕命令、按钮或自动任务。
2. **两个安装包**：产品分为 **免费版安装包** 和 **会员版安装包**，是两个独立发布的应用。
3. **免费版安装包**：只包含免费版功能，**没有任何充值入口、没有任何会员引导、没有任何会员功能入口**。
4. **会员版安装包**：默认只显示免费版功能，**有会员充值入口**；用户充值成功后，才下载完整会员功能模块并启用。
5. **会员登录**：会员版安装包通过 **B 站扫码登录** 完成身份绑定，Rust 端直接调用社区维护的扫码登录 API，不经过自建后端。保留「手动输入 UID」作为降级方案。
6. **到期暂停、续费恢复**：会员到期后，会员部分功能暂停，已下载模块保留；续费后无需重新下载，直接恢复使用。
7. **Sidecar 合规**：FFmpeg 使用现成 LGPL 预编译构建，随主包分发；whisper.cpp 二进制随会员模块下载；whisper 模型按需下载。
8. **本地优先**：监听、过滤、统计、录制、AI 预览均以本地为主，默认不上传用户数据。
9. **数据统计与展示为两个安装包共有底座**：数据看板、排行榜、数据导出、历史查询、数据保留策略，免费版与会员版一致，不因会员状态而裁剪。

## 1. 产品概述

### 1.1 产品愿景

打造一款集观众弹幕监控、智能观测、特效展示、直播录制、数据分析于一体的 Bilibili 直播辅助工具，帮助主播降低直播运营成本，实时掌握直播间观众互动情况，同时满足内容存档和二次创作需求。

产品以两个独立安装包交付，通过会员体系区分能力：

1. **免费版安装包**：纯直播间只读数据监听、本地提醒、数据统计、风控管理（不含自动禁言）、弹幕语音播报、直播录制、插件系统、多语言、基础 UI。**无任何充值入口，无任何会员引导，无任何自动发送弹幕能力**，合规无风险。
2. **会员版安装包**：默认只显示免费版功能，提供会员充值入口。用户充值成功后，自动下载会员功能模块并启用，增加自动禁言与刷屏防护、AI 文案辅助系统。AI 支持自定义人设、结合直播间上下文生成本地回复建议与摘要，所有结果仅在工具内预览，不主动发送至直播间。

### 1.2 目标用户

- Bilibili 全职/兼职游戏、娱乐、虚拟主播
- 直播间运营团队成员，负责直播复盘、互动运营
- 需要 24 小时无人值守挂机监控、维持直播间基础互动的虚拟主播、挂机直播间运营者

## 2. 重构概述

### 2.1 重构背景

原产品功能覆盖弹幕监听、风控、提醒、TTS、录制、AI 文案辅助等模块。为降低内存占用、提升并发性能、增强安全隔离、支持插件沙箱和跨平台发布，决定采用 Tauri 框架重构。

Tauri 的核心优势：

- Rust 后端处理 WebSocket、规则引擎、录制、AI 调用、数据库等高负载任务。
- WebView 前端只负责 UI 渲染，降低内存占用。
- 通过 IPC Command / Event 实现前后端解耦。
- 通过 Capabilities 权限系统限制前端能力。
- 支持 Sidecar 集成 ffmpeg、whisper.cpp 等本地二进制。
- 支持自动更新、系统托盘、全局快捷键、通知、多窗口透明特效。

### 2.2 重构目标

1. 保持原产品全部免费/会员功能，产品体验不降级。
2. 核心能力 Rust 化：WebSocket、敏感词、刷屏检测、录制控制、TTS 队列、AI 调用、数据库、扫码登录。
3. 前端轻量化：仅通过 `invoke` 和 `listen` 与 Rust 交互，不直接访问文件系统、数据库和密钥。
4. 安全增强：所有 IPC 命令在 Rust 侧做参数校验、类型校验、路径白名单。
5. 性能提升：空闲内存 ≤120MB，录制+AI 模式内存 ≤200MB，CPU 增量 ≤15%。
6. 插件沙箱：WASM 沙箱 + 独立实例隔离，崩溃不影响主进程。
7. 发布现代化：双安装包、应用内会员、模块按需下载、多通道更新、灰度发布、签名校验、回滚。

### 2.3 重构原则

- **本地优先**：监听、过滤、统计、录制、AI 预览、扫码登录均以本地为主。
- **只读监听**：B 站 WebSocket 仅接收事件，不设计发送弹幕命令。
- **权限最小化**：Tauri Capabilities 按窗口分配权限，IPC 命令在 Rust 侧二次校验。
- **模块解耦**：AI 异常不影响监听、提醒、统计和录制。
- **数据兼容**：历史配置、日志、统计可迁移，迁移失败自动回滚。
- **可观测**：Rust `tracing` + 前端日志面板 + 本地日志文件 + 业务埋点。
- **底座一致**：数据统计与展示为两个安装包共有，不因会员状态而裁剪。
- **免费版零付费干扰**：免费版安装包不出现任何充值、会员、升级引导。
- **会员功能可下载、可暂停、可恢复**：会员功能模块独立于主包，按需下载，到期暂停，续费恢复。
- **登录不留服务端**：B 站扫码登录完全在应用内 Rust 侧完成，不依赖自建后端。

### 2.4 成功指标与测试前置条件

所有性能指标必须定义测试前置条件，避免验收扯皮。

| 指标             | 目标    | 测试前置条件                                                 |
| ---------------- | ------- | ------------------------------------------------------------ |
| 冷启动时间       | ≤2 秒   | 应用启动到主窗口可交互，Sidecar 未启动                       |
| 空闲内存         | ≤120MB  | 启动后连接 1 个直播间，未录制，未开 AI，Sidecar 未启动       |
| 录制+AI 内存     | ≤200MB  | 会员已激活：录制中 + ASR 开启 + whisper-small 已加载 + LLM 空闲 |
| CPU 增量         | ≤15%    | 录制中 + 1000 条/秒弹幕 + AI 空闲                            |
| 弹幕接收延迟     | ＜100ms | 单房间，1000 条/秒，本地网络                                 |
| AI 生成总延迟    | ≤5 秒   | 本地组装 ≤500ms，LLM 请求 ≤4.5s，网络正常                    |
| 自动重连成功率   | ≥95%    | 模拟断网 10 次，每次断 5 秒                                  |
| 免费版安装包体积 | ≤60MB   | 含 FFmpeg LGPL shared，不含会员模块、不含 whisper 模型       |
| 会员版安装包体积 | ≤60MB   | 与免费版主包一致，不含会员模块、不含 whisper 模型            |

| 扫码登录成功耗时 | ≤30 秒  | 用户扫码并确认后，到登录成功的总耗时                         |
| 可用率           | ≥99.5%  | 排除版本更新停机                                             |

## 4. 版本策略与用户群体

### 4.1 双安装包矩阵

产品以两个独立安装包发布。两个安装包代码基础相同，构建配置不同。

| 安装包       | 面向用户           | 默认功能   | 充值入口 | 登录入口 | 会员模块下载   |
| ------------ | ------------------ | ---------- | -------- | -------- | -------------- |
| 免费版安装包 | 所有用户           | 免费版功能 | 无       | 无       | 无             |
| 会员版安装包 | 需要会员功能的用户 | 免费版功能 | 有       | 有       | 充值成功后下载 |

### 4.2 免费版安装包行为

- 只显示免费版功能入口。
- 不显示会员中心、AI 助手、刷屏防护入口。
- 不显示任何登录、升级引导、会员广告、充值按钮。
- 不包含会员模块下载能力。
- 不包含会员鉴权逻辑。
- 不包含 B 站扫码登录逻辑。
- 用户完全感知不到会员体系与登录体系的存在。

### 4.3 会员版安装包行为

- 默认只显示免费版功能入口。
- 顶部工具栏显示「登录 / 开通会员」按钮。
- 左侧导航显示「会员中心」入口。
- 不显示 AI 助手、刷屏防护入口（未充值前）。
- 用户登录后，可查看套餐并充值。
- 充值成功后：
  - 自动下载 AI 模块、自动禁言模块。
  - 下载完成后显示 AI 助手、刷屏防护入口。
  - 顶部工具栏显示会员到期时间。
- 会员到期后：
  - AI 助手、刷屏防护入口置灰。
  - 顶部工具栏显示「续费」。
  - 已下载模块保留。
  - 续费后立即恢复。

### 4.4 共有底座能力

以下能力为两个安装包共有，不因版本差异而裁剪：

| 能力           | 说明                                                     |
| -------------- | -------------------------------------------------------- |
| 实时数据看板   | 在线人数、弹幕量、弹幕速率、礼物收益、舰长数据及趋势曲线 |
| 排行榜         | 送礼榜、弹幕互动榜、舰长贡献榜，实时更新                 |
| 数据导出       | 看板数据、榜单数据导出 CSV                               |
| 历史数据查询   | 按时间范围查询历史统计                                   |
| 数据保留与清理 | 统一保留策略，两个版本一致                               |

### 4.5 数据目录策略

- 两个安装包使用相同应用标识符与数据目录。
- 免费版安装包升级到会员版安装包：覆盖安装，数据保留。
- 会员版安装包降级到免费版安装包：提示会员模块与登录信息将不可用，建议先导出配置。
- 会员模块存放在 `modules/` 子目录，与主包隔离。
- 登录信息存放在 `account.json`，与主包配置分离。
- 会员到期不删除模块，续费后直接复用。

## 5. 会员体系与模块策略

### 5.1 会员模型

产品有两个独立安装包。免费版安装包无会员体系；会员版安装包提供应用内登录与付费，付费后下载会员功能模块。

| 状态         | 免费版安装包 | 会员版安装包                          |
| ------------ | ------------ | ------------------------------------- |
| 未登录       | 不适用       | 免费版功能可用；显示登录/开通会员入口 |
| 已登录未付费 | 不适用       | 免费版功能可用；显示套餐与充值入口    |
| 付费成功     | 不适用       | 自动下载并启用会员模块；显示会员入口  |
| 会员到期     | 不适用       | 会员功能暂停；入口置灰；显示续费      |
| 续费成功     | 不适用       | 无需重新下载；立即恢复                |

### 5.2 会员功能模块清单

会员功能以独立模块包形式下载，与主包分离。

| 模块         | 内容                                                     | 形式                 |
| ------------ | -------------------------------------------------------- | -------------------- |
| AI 模块      | AI 前端资源、whisper.cpp Sidecar 二进制、AI 相关配置文件 | 前端资源包 + Sidecar |
| 自动禁言模块 | 刷屏防护前端资源、规则配置模板、Cookie 管理接口调用配置  | 前端资源包 + 配置    |
| 会员中心模块 | 会员中心页面、订单记录、续费入口                         | 前端资源包           |

> 核心 Rust 逻辑（LLM 代理、规则引擎、Cookie 接口调用、扫码登录）预编译在会员版主程序中，通过运行时会员状态控制是否启用。免费版主程序不包含这些 Rust 逻辑。

### 5.3 模块下载与安装流程

1. 用户在会员中心点击「开通会员」。
2. 前端调用 `membership_purchase(plan_id)`。
3. Rust 通过 `reqwest` 向服务端发起支付请求，返回支付二维码或支付链接。
4. 前端展示支付二维码，用户扫码支付。
5. Rust 轮询支付状态，成功后服务端返回：
   - 会员签名令牌（Ed25519 签名，含有效期）。
   - 模块清单（模块名、版本、下载地址、哈希）。
6. Rust 校验令牌签名，写入 `t_membership`。
7. Rust 依次下载模块包：
   - 下载到临时目录。
   - 校验哈希。
   - 解压到 `modules/<module_name>/<version>/`。
   - 写入 `t_module`。
8. 下载完成后推送 `module_installed` 事件。
9. 前端动态加载会员模块资源，Rust 启动对应 Sidecar。
10. 会员功能入口显示，用户可正常使用。

### 5.4 到期暂停流程

1. Rust 每次启动、每小时定时、每次会员功能调用前校验令牌有效期。
2. 令牌过期后：
   - Rust 停止会员相关服务（ASR、LLM 代理、自动禁言）。
   - 关闭会员 Sidecar。
   - 推送 `membership_expired` 事件。
3. 前端：
   - 隐藏或置灰会员功能入口。
   - 显示续费引导。
   - 已下载模块保留，不删除。
4. 用户可继续使用全部免费版功能。

### 5.5 续费恢复流程

1. 用户在会员中心点击「续费」。
2. 重复 5.3 的支付流程。
3. 支付成功后服务端返回新令牌。
4. Rust 校验签名，更新 `t_membership`。
5. 若模块已下载且版本一致，跳过下载，直接加载。
6. 若模块有新版本，按 5.3 流程更新。
7. 推送 `membership_renewed` 事件。
8. 前端恢复会员功能入口，Rust 重启会员服务。

### 5.6 会员鉴权

| 项目       | 说明                                                 |
| ---------- | ---------------------------------------------------- |
| 签名算法   | Ed25519                                              |
| 公钥位置   | 硬编码在会员版 Rust 二进制，不存数据库；免费版不包含 |
| 令牌内容   | 用户 UID、会员等级、有效期、签发时间、随机数         |
| 校验位置   | Rust 侧，前端无法拿到校验结果原文                    |
| 本地存储   | `t_membership` 加密存储，字段带签名                  |
| 防篡改     | 修改数据库字段导致签名失效，会员状态失效             |
| 离线有效期 | 默认 7 天，超时必须联网校验                          |
| 联网校验   | 每日一次心跳，异常时降级为离线有效期                 |
| 令牌刷新   | 有效期内自动刷新，避免频繁登录                       |

### 5.7 模块加载

### 6.3 用户场景

#### 场景 1：免费版用户日常使用

**背景**：兼职主播小李下载免费版安装包，日常直播使用。

**流程**：
1. 小李从官方渠道下载免费版安装包。
2. 安装后启动，界面只显示免费版功能入口。
3. 小李看不到任何充值、会员、升级引导。
4. 小李连接直播间，使用弹幕监控、语音播报、数据看板、直播录制。
5. 所有免费版功能正常使用。

#### 场景 2：会员版用户扫码登录

**背景**：全职主播小王下载会员版安装包，决定开通会员。

**流程**：
1. 小王下载会员版安装包并安装。
2. 启动后界面只显示免费版功能，顶部显示「登录 / 开通会员」。
3. 小王点击「登录」，弹出 B 站扫码登录窗口。
4. Rust 向 B 站 passport 接口请求二维码，本地渲染为 PNG，前端展示。
5. 小王用 B 站 App 扫码并确认。
6. Rust 轮询到登录成功，提取 UID、昵称、头像，写入 `account.json`。
7. 前端显示登录成功，顶部显示「开通会员」。
8. 小王点击「开通会员」，进入会员中心。

#### 场景 3：会员版用户应用内付费

**背景**：小王登录后，决定开通年付会员。

**流程**：
1. 小王在会员中心选择年付套餐。
2. 点击「选择」，Rust 向服务端请求订单，返回支付二维码。
3. 小王扫码支付。
4. Rust 轮询订单状态，支付成功后返回会员令牌与模块清单。
5. Rust 校验令牌签名，依次下载 AI 模块、自动禁言模块。
6. 下载完成后，AI 助手、刷屏防护入口显示。
7. 小王配置 AI 人设、LLM Provider、whisper 模型。
8. 会员功能立即可用。

#### 场景 4：会员到期暂停与续费恢复

**背景**：会员到期，会员功能暂停；续费后恢复。

**流程**：
1. 会员到期前 7 天，应用内提醒续费。
2. 到期后，AI 助手、刷屏防护入口置灰，提示续费。
3. 已下载模块保留，不删除。
4. 主播在会员中心点击「续费」，扫码支付。
5. 支付成功后，无需重新下载，会员功能立即恢复。
6. 若模块有新版本，提示更新。

#### 场景 5：扫码登录不可用时的降级

**背景**：B 站 passport 接口变动，扫码登录暂时失效。

**流程**：
1. 用户点击「登录」，扫码窗口打开。
2. Rust 请求二维码失败，或轮询持续报错。
3. 前端显示「扫码登录暂不可用」。
4. 提供「手动输入 UID」入口。
5. 用户输入 UID，Rust 调用 B 站公开 API 获取昵称头像。
6. 用户确认后，绑定 UID，写入 `account.json`。
7. 用户可继续完成会员充值。

#### 场景 6：夜间挂机直播监控（免费版功能）

**背景**：主播休息，直播间挂机运行，工具仅做数据监听与本地提醒。

**流程**：
1. 主播连接直播间，开启弹幕语音播报、礼物/上舰提醒功能。
2. 配置敏感词过滤、黑名单规则，维护直播间秩序。
3. 工具后台静默监听直播间全量事件，无任何主动操作。
4. 观众发送弹幕，工具本地展示、语音播报、留存日志。
5. 触发舰长、大额礼物事件，工具弹窗 + 音效提醒。
6. 主播次日通过数据看板、日志复盘整场直播数据与互动情况。

#### 场景 7：AI 回复建议生成（会员功能）

**背景**：主播直播过程中，使用 AI 生成符合人设的本地回复建议。

**流程**：
1. 主播提前配置 AI 人设、模型参数、敏感词和上下文范围。
2. 主播在工具内输入问题或选择已有上下文，主动发起文案生成。
3. AI 结合上下文与人设生成回复建议。
4. 生成结果经过敏感词过滤后仅在工具内展示。
5. 主播可重新生成或调整输入，不产生直播间发送副作用。
6. AI 生成、拦截和失败记录可留存日志，支持复盘导出。

#### 场景 8：高光时刻自动录制（免费版功能）

**背景**：主播进行高难度游戏挑战，需要自动捕捉精彩瞬间。

**流程**：
1. 系统实时监测直播间弹幕热度、礼物波动数据。
2. 检测到弹幕激增、热度暴涨，自动判定为高光时刻。
3. 自动录制高光前后 30 秒片段，独立保存为 MP4 文件。
4. 主播也可通过 F9 快捷键手动标记高光时刻。
5. 直播结束后，主播可手动剪辑、上传高光片段至 B 站。

#### 场景 9：舰长开通专属特效提醒（免费版功能）

**背景**：观众首次/续费开通舰长，主播需要醒目提醒。

**流程**：
1. 工具监听直播间舰长开通事件，识别首次开通/续费类型。
2. 本地独立窗口弹出专属金色视觉特效，播放定制欢迎音效。
3. 本地日志记录感谢文案，仅工具内展示，不对外发送弹幕。
4. 特效停留 5 秒后自动淡出，不影响直播画面。

#### 场景 10：全场直播存档录制（免费版功能）

**背景**：重要直播场次，需要全程存档用于后期复盘与二次创作。

**流程**：
1. 主播连接直播间后，手动开启全程录制功能。
2. 工具实时拉取直播流，无损录制并实时标记高光节点。
3. 直播结束后停止录制，自动生成完整录播文件与独立高光片段。
4. 主播可本地预览、剪辑、手动上传至 B 站平台。

#### 场景 11：自动禁言维护秩序（会员功能）

**背景**：直播间出现刷屏、广告等违规行为，会员版自动识别并处理。

**流程**：
1. 会员版用户在风控中心首次启用自动禁言，完成风险确认。
2. Rust 规则引擎实时检测刷屏、重复、相似内容。
3. 命中规则后调用本地 Cookie 管理接口执行禁言。
4. 禁言结果写入日志，前端展示系统提示。
5. 接口不可用时自动降级为本地告警，由用户手动处理。

### 9.1 直播间连接与弹幕接收（免费）

#### 9.1.1 功能描述

通过 WebSocket 全量连接 Bilibili 直播间，实时接收观众弹幕流、直播间各类事件流，毫秒级同步展示在本地面板，**仅做只读接收，无任何主动发送、操作直播间权限**。

#### 9.1.2 业务流程

1. 用户在顶部工具栏点击「房间选择」下拉，选择或新增房间。
2. 用户点击「连接」按钮。
3. 前端调用 `room_connect(room_id)`，Rust 侧 `IpcGuard` 校验房间号格式、长度、白名单。
4. Rust 通过 `reqwest` 请求房间初始化信息，获取弹幕服务器地址与 Token。
5. Rust 建立 `tokio-tungstenite` WebSocket 长连接，完成鉴权握手。
6. 连接成功后，Rust 通过 `room_status_changed` 事件推送前端，状态栏变绿。
7. Rust 持续接收事件帧，解析为 `DanmuEvent` / `GiftEvent` / `CaptainEvent` / `EnterEvent`。
8. 解析后经敏感词、黑名单、身份识别过滤，通过 `danmu_received` 等事件推送前端。
9. 前端弹幕面板逐条追加展示，同时写入 `t_event_log`。
10. 网络断开时，Rust 自动重试重连，最多 10 次，间隔 5 秒，期间缓存事件。
11. 重连成功后补全缓存事件，前端无感知。
12. 用户点击「断开」或关闭房间，触发 `room_disconnect`，Rust 关闭连接并清理资源。

### 9.2 分级用户身份识别（免费）

#### 9.2.1 功能描述

#### 9.2.2 业务流程

1. Rust 接收弹幕事件，解析 `user_info` 字段。
2. 根据 `guard_level` 判断总督/提督/舰长。

7. 前端按标签渲染颜色与图标。
8. 用户点击用户名，展示完整身份详情。

### 9.3 敏感词过滤（免费）

#### 9.3.1 功能描述

内置分级敏感词库，支持自定义词汇，自动拦截违规、广告、引战弹幕，屏蔽展示与语音播报，完整留存过滤日志。

#### 9.3.2 业务流程

1. Rust 在弹幕进入 EventBus 前，先经敏感词引擎。
2. 引擎使用 Aho-Corasick 匹配精确词，正则匹配模糊规则。
3. 命中后根据词类型决定处理：直接屏蔽 / 替换 / 仅记录。
4. 命中弹幕不进入前端展示、不进入 TTS 队列、不进入 AI 上下文。
5. 写入 `t_event_log`，标记 `filtered=true` 与命中词。
6. 前端弹幕面板底部「已过滤数」+1。
7. 用户在风控中心可查看、新增、删除、导入、导出词库。

#### 9.3.3 界面设计

### 9.4 自动禁言与刷屏防护（会员）

#### 9.4.1 功能描述

基于频率、重复度、相似度规则识别刷屏违规用户。**本功能仅在会员版安装包且会员激活时可用**，使用主播本地账号 Cookie 能力调用 B 站管理接口，**不属于开放平台标准 API**，不承诺可用性，接口变动随时下线。自动禁言默认关闭，首次启用需独立风险确认。会员到期后，自动禁言暂停。

#### 9.4.2 业务流程

1. Rust 规则引擎在弹幕进入时记录用户行为滑动窗口。
2. 每次新弹幕触发三条规则检测：频率、重复、相似度。
3. 命中任一规则，标记该用户为「待处理」。
4. 若用户已开启自动禁言，且已完成风险确认，且会员处于激活状态，Rust 调用本地 Cookie 管理接口。
5. 禁言成功后写入 `t_event_log` 与审计日志，推送 `user_muted` 事件。
6. 前端弹幕面板显示系统提示「用户X 因刷屏已被禁言」。
7. 若未开启自动禁言，仅在风控中心生成待处理告警，由用户手动确认。
8. 会员到期后，自动禁言暂停，只生成本地告警。
9. 用户可在风控中心查看历史禁言记录、申诉、解除。

#### 9.4.3 界面设计

**页面位置**：左侧导航「风控中心 → 刷屏防护」。会员版未登录或未付费时不显示此入口；会员激活后显示完整功能；到期后置灰并提示续费。

### 9.13 直播录制（免费）

#### 9.13.1 功能描述

#### 9.13.2 业务流程

1. 用户在直播录制页点击「开始录制」。
2. 前端调用 `recording_start(room_id, options)`，Rust 校验参数与路径。
3. Rust 启动 ffmpeg Sidecar（LGPL 构建），拉流录制。
4. 同时维护环形缓冲：内存缓冲保存最近 60 秒，磁盘缓冲用于长时间录制。
5. 检测到弹幕热度激增，自动标记高光，截取前后 30 秒。
6. 用户按 F9 手动标记高光。
7. 录制结束，Rust 停止 ffmpeg，生成文件与高光片段。
8. 写入 `t_recording` 与 `t_highlight`。
9. 前端录制管理页展示文件列表。

#### 9.13.3 FFmpeg 许可与分发

- 使用 BtbN 或 gyan.dev 的 **LGPL 预编译构建**，不启用 GPL/nonfree 组件。
- 推荐 **shared** 构建，合规更简单。
- 安装包「关于」页面附 FFmpeg LGPL 许可证全文与源码获取地址。
- 允许用户外接本机 FFmpeg 作为备选。
- 录制设置中提供「使用本机 FFmpeg」选项。

#### 9.13.4 环形缓冲磁盘保护

| 策略         | 说明                                     |
| ------------ | ---------------------------------------- |
| 内存缓冲     | 保存最近 60 秒，用于短时高光截取         |
| 磁盘缓冲     | 长时间录制时，写入临时文件，设置配额上限 |
| 磁盘配额     | 默认 10GB，可配置                        |
| 水位保护     | 磁盘剩余低于 5GB 时停止录制并告警        |
| 自动清理     | 到达配额时自动清理最旧缓冲               |
| 录制文件配额 | 录制目录总量可配置上限                   |

### 9.14 AI 文案辅助模块（会员）

#### 9.14.1 功能描述

会员功能。本地生成、本地预览，不自动触发，不发送弹幕。整合离线 ASR、自定义人设、上下文记忆、内容过滤与本地回复建议。会员到期后暂停，续费后恢复。

#### 9.14.2 业务流程

1. 用户完成会员付费，模块下载并安装。
2. 用户在系统设置中配置 LLM Provider、API Key、模型、温度、最大长度。
3. 用户在 AI 人设页配置身份、风格、系统提示词、敏感词、上下文窗口。
4. 用户首次启用 ASR 时，提示下载 whisper 模型，展示许可证，选择档位。
5. Rust 通过 whisper.cpp Sidecar 采集麦克风并缓存最近 30 秒。
6. 用户在 AI 面板输入提示词，或选择上下文片段。
7. 点击「生成」，前端调用 `ai_generate`。
8. Rust 校验会员状态，组装上下文（人设 + 弹幕 + ASR + 人工输入），调用 LLM。
9. 流式返回，通过 `ai_generation_delta` 推送前端。
10. 生成完成后本地敏感词过滤 + 长度截断。
11. 结果仅在 AI 面板展示，提供「重新生成」「复制」「清空」。
12. 写入 `t_ai_log`，不记录发送状态。
13. 不存在任何发送按钮或 Command。
14. 会员到期后，`ai_generate` 返回 `membership_required`，前端提示续费。

### 9.15 B 站扫码登录（会员版专属）

#### 9.15.1 功能描述

会员版安装包专属。通过 B 站扫码登录完成身份绑定，Rust 端直接调用社区维护的扫码登录 API，不经过自建后端。登录成功后提取 `DedeUserID`（B 站 UID）作为用户唯一标识，用于会员绑定。保留「手动输入 UID」作为降级方案。

#### 9.15.2 业务流程

**扫码登录流程**：

1. 用户在会员中心或顶部工具栏点击「登录」。
2. 前端调用 `auth_qrcode_generate`。
3. Rust 向 `https://passport.bilibili.com/x/passport-login/web/qrcode/generate` 请求二维码。
4. Rust 拿到 `qrcode_key` 和 `url`。
5. Rust 用 `qrcode` crate 将 `url` 渲染为 PNG，base64 编码。
6. Rust 返回 `qrcode_key` 和 `qrcode_image_base64` 给前端。
7. Rust 启动轮询任务，每 2 秒请求 `poll` 接口。
8. 前端展示二维码，提示「请使用 B 站 App 扫码」。
9. 用户用 B 站 App 扫码并确认。
10. Rust 轮询到状态码 `0`，登录成功，Cookie 已由 `reqwest::Client` 的 cookie_store 保存。
11. Rust 用同一 Client 调用 `https://api.bilibili.com/x/web-interface/nav` 获取用户信息。
12. Rust 提取 UID、昵称、头像，写入 `account.json`。
13. Rust 通过 `auth_qrcode_status` 事件推送 `Success { user }` 给前端。
14. 前端展示登录成功，顶部工具栏更新为「开通会员」或到期时间。

**状态码映射**：

| B 站 data.code | 含义         | 映射为    |
| -------------- | ------------ | --------- |
| 86101          | 未扫码       | `Pending` |
| 86090          | 已扫码未确认 | `Scanned` |
| 0              | 登录成功     | `Success` |
| 86038          | 二维码失效   | `Expired` |
| 其他           | 未知         | `Error`   |

**手动输入 UID 降级流程**：

1. 用户在扫码窗口点击「扫码不可用？手动输入 UID」。
2. 用户输入 UID。
3. Rust 调用 `https://api.bilibili.com/x/space/acc/info?mid=<uid>` 获取昵称头像。
4. 前端展示昵称、头像、UID，用户确认。
5. 用户确认后，Rust 写入 `account.json`。
6. 推送 `auth_logged_in` 事件。

#### 9.15.6 Rust 侧实现要点

**独立 Client 隔离 Cookie**：

- 每个登录会话使用独立 `reqwest::Client`，开启 `cookie_store(true)`。
- 多个用户轮流登录时，Cookie 不串联。
- 重新登录时，旧 Client 随旧任务一起丢弃。

**Cookie 不落盘**：

- 登录成功后，Cookie 仅保存在内存中的 `reqwest::Client`。
- 只把 UID、昵称、头像写入 `account.json`。
- 后续自动禁言需要 Cookie 时，单独处理加密存储，不在登录环节引入。

**轮询在 Rust 侧异步任务完成**：

- 前端不参与轮询，只接收 `auth_qrcode_status` 事件。
- 即使前端切换页面、关闭弹窗，轮询仍在继续，状态不会丢。
- 用户点击取消时，调用 `auth_qrcode_cancel` 主动 abort 任务。

**二维码在 Rust 侧生成**：

- B 站返回的是 `url`，不是二维码图片。
- Rust 用 `qrcode` crate 把 url 渲染成 PNG。
- base64 编码后传给前端，前端直接 `<img>` 展示。

**连续失败保护**：

- 轮询连续失败 5 次才报错，避免网络抖动导致误报。
- 正常每 2 秒一次，二维码有效期 180 秒，最多轮询 90 次。

#### 9.15.7 登录令牌

| 项目           | 说明                                                  |
| -------------- | ----------------------------------------------------- |
| 来源           | 本地生成，不依赖后端                                  |
| 内容           | UID、昵称、头像、登录时间                             |
| 存储           | `account.json`，明文存储（UID、昵称、头像是公开信息） |
| 有效期         | 无过期，直到用户主动退出登录                          |
| 用途           | 作为会员绑定的用户标识                                |
| 与会员令牌关系 | 登录令牌证明身份，会员令牌证明付费，两者分离          |

#### 9.15.8 异常处理

| 异常                  | 处理                                       |
| --------------------- | ------------------------------------------ |
| 二维码请求失败        | 提示「扫码登录暂不可用」，引导手动输入 UID |
| 轮询连续失败 5 次     | 推送 `Error`，提示用户重试或手动输入       |
| 二维码失效            | 推送 `Expired`，提供刷新按钮               |
| nav 接口失败          | 提示登录失败，保留 Cookie 供重试           |
| 网络断开              | 轮询暂停，网络恢复后继续                   |
| 手动输入 UID 查询失败 | 提示「UID 无效或查询失败」，允许重新输入   |
| B 站接口变动          | 版本更新适配，异常期间引导手动输入         |

#### 9.15.9 风险声明

必须在用户协议和 PRD 中明确：

- 本登录使用 B 站非官方 passport 接口，不属于开放平台 OAuth 体系。
- 接口变动可能导致登录功能失效，不承诺可用性。
- 登录过程中会临时获取 Cookie，仅用于本次会话获取用户信息，不落盘、不上传。
- 使用本功能产生的任何风险由用户自行承担。
- 保留手动输入 UID 作为降级方案，保证核心功能不因单一接口失效而中断。

#### 9.15.10 验收标准

1. 扫码后 30 秒内登录成功。
2. 登录成功后展示昵称、头像、UID。
3. 扫码不可用时提供 UID 输入入口。
4. UID 输入后展示昵称头像确认。
5. 登录信息写入 `account.json`。
6. Cookie 不落盘。
7. 连续轮询失败 5 次后报错。
8. 二维码失效后可刷新。
9. 免费版安装包不包含此功能。

### 9.16 会员中心（会员版专属）

#### 9.16.1 功能描述

会员版安装包专属。提供登录、套餐选择、支付、模块下载、订单查询、续费、模块管理。免费版安装包不包含此页面。

#### 9.16.2 业务流程

**登录流程**：见 9.15。

**付费流程**：
1. 用户在会员中心选择套餐（月付/季付/年付）。
2. 前端调用 `membership_purchase(plan_id)`。
3. Rust 向服务端请求订单，返回支付二维码或支付链接。
4. 前端展示支付二维码，用户扫码支付。
5. Rust 轮询订单状态，成功后服务端返回会员令牌与模块清单。
6. Rust 校验令牌签名，写入 `t_membership`。
7. Rust 依次下载模块包，校验哈希，解压到模块目录。
8. 推送 `module_installed`，前端加载会员功能入口。

**到期检测流程**：
1. Rust 每次启动、每小时定时、每次会员功能调用前校验令牌。
2. 令牌过期后停止会员服务，推送 `membership_expired`。
3. 前端置灰会员入口，显示续费引导。

**续费流程**：
1. 用户在会员中心点击「续费」。
2. 重复付费流程。
3. 支付成功后更新令牌，检查模块版本。
4. 无需重新下载时直接加载，推送 `membership_renewed`。

## 10. IPC 安全与参数校验

### 10.1 设计原则

- 所有 Tauri Command 在 Rust 侧做参数校验、类型校验、范围校验、路径白名单。
- 前端不直接访问文件系统、数据库、密钥。
- 文件操作强制走系统文件对话框，禁止前端传入任意本地路径。
- 特效窗口独立 Capability，不授予任何 IPC 命令。
- 会员相关 Command 在会员版 Rust 侧额外校验会员状态；免费版不注册这些 Command。
- 登录相关 Command 在会员版 Rust 侧注册；免费版不注册。

### 10.2 校验规则

| 参数类型   | 校验规则                                 |
| ---------- | ---------------------------------------- |
| 房间号     | 数字字符串，长度 1-20                    |
| UID        | 数字字符串，长度 1-20                    |
| 用户名     | 长度 1-50，去除控制字符                  |
| 文件路径   | 仅允许系统对话框返回的路径，禁止前端拼接 |
| 音量       | 0-1 浮点                                 |
| 阈值       | 非负整数                                 |
| 时间范围   | 枚举值                                   |
| 敏感词     | 长度 1-100，去除控制字符                 |
| 模板       | 变量名白名单校验                         |
| 套餐 ID    | 白名单枚举                               |
| 模块名     | 白名单枚举                               |
| 二维码 key | 长度 1-64，仅字母数字                    |

### 10.3 路径白名单

- 录制目录、导出目录由用户在设置中选择，存入配置。
- IPC 命令只接受配置中的路径，不接受前端传入的任意路径。
- 文件选择通过 `tauri-plugin-dialog` 完成，返回路径由 Rust 校验后使用。
- 模块下载目录由 Rust 管理，前端不可指定。
- `account.json` 路径由 Rust 管理，前端不可指定。

### 10.4 会员与登录相关命令校验

仅会员版注册以下命令：

| 命令                   | 校验                                   |
| ---------------------- | -------------------------------------- |
| `auth_qrcode_generate` | 无参数，Rust 内部限制并发 1 个会话     |
| `auth_qrcode_cancel`   | 无参数                                 |
| `auth_query_uid`       | UID 格式校验                           |
| `auth_bind_uid`        | UID 格式校验                           |
| `auth_logout`          | 无参数                                 |
| `auth_current_account` | 无参数                                 |
| `membership_purchase`  | 校验套餐 ID、登录状态                  |
| `ai_generate`          | 校验会员激活、模块已安装、LLM 配置完整 |
| `moderate_mute`        | 校验会员                               |
